# 第 5-B 步：运动区间查询

日期：2026-10-06 · 版本：v0.1 · 任务等级：L3 · 状态：实施设计已展开，功能待制作

前置：[5-A2：静态内切与外接判定](05-A2-静态内切与外接判定.md)。整体安排见[第五步：加入目标判定](05-第五步-内切与外接判定.md)，目录按[当前分类](../../架构设计/数学桌球-脚本目录归属约定.md)：判定器在 Core/Rules，本局在 Core/Session，模拟组件在 Core/Ball/Components，管理器在 Module/对应名称Module。本次继续文档，不代表前置功能已验收。

## 1. 本步目标与边界

查询一个模拟区间内是否曾满足内切或外接条件；若满足，返回最早达成的候选时刻及该时刻的真实球状态。球快速经过目标时，即使区间起点和终点都未达成，中途短暂贴合也应识别。

本步完善 GoalJudge 的区间查询，并让 Session 协调只读查询、复核和事件比较。先通过纯逻辑与开发验证入口检查候选结果；正式提交命中状态、停止模拟及一次成功提示在 5-C 接入。候选结果不直接触发游戏通关，也不新增完整结算、道具或尝试循环。

## 2. 对象职责与查询顺序

| 对象 | 本步增加的内容 |
|---|---|
| `BallSimulationComponent` | 从当前杆的确定轨迹准备只读查询段，提供同一时刻的球心、半径和速度；查询不推进状态 |
| `BilliardsGoalJudge` | 沿用静态规则，求目标在区间内成立的时间集合，返回最早候选；不读写球对象 |
| `BilliardsSession` | 限定查询范围，协调目标与边界事件，复核候选，得到可交给下一阶段的结果 |
| `BallManager`、`BallBase` | 沿用现有访问和状态同步能力，不增加几何规则或独立计时 |
| `LevelManager` | 提供稳定的目标、容差、桌面范围等只读关卡数据，不负责逐步模拟或事件排序 |

流程为“准备只读轨迹 → 按规则变化时刻分段 → 查询最早目标候选 → 比较边界等候选 → 返回本次查询结果”。几何计算和模块内部协调使用直接调用；本步没有新增 UI 通知或跨模块事件。

不建立第二个运动控制器、求解管理器、判定组件或通用策略体系。分段、内切、外接及必要求根组织成已有对象的内部方法；实际文件位置与复用类型在实施时核对。

## 3. 使用已有连续轨迹

沿用[固定路程运动](03-第三步-固定路程运动.md)与[大小变化](04-第四步-球的大小变化.md)的数学模型，位置和半径共用本杆累计模拟时间，不能分别使用帧时间。

在一段内用局部时间 `τ = t - ts` 表达：

- 球心：`C(τ) = Cs + Vs·τ + 0.5·A·τ²`。
- 速度：`V(τ) = Vs + A·τ`。
- 半径：`r(τ) = rs + k·τ`，达到上下限后的段取 `k = 0`。

其中 `ts` 是段起始的本杆累计时间；`Cs、Vs、rs` 都取该时刻的真实值。当前直线恒减速方案的加速度方向与速度相反，停止后不延伸二次轨迹产生倒退。公式用于表达已有能力，不新增第二套运动积分。

按半径上下限、自然停止等确定时刻分段；若已有趋势切换，则从切换时刻用连续半径建立新段。本步不制作玩家道具。自然停止时位置与半径都停止推进，查询只到停止时刻，并包含该终点。

准备阶段需提供可重建连续函数的只读参数或等价数据，仅提供“任意时刻回调”但没有可求解的轨迹结构还不足以保证完整查询。若实际实现与规划模型不同，先核对其连续表达和可靠求解能力，不能自行改成线性插值或假定为二次轨迹。

## 4. 输入、时间与结果约定

输入包括有效的目标与容差快照、查询范围 `[ta, tb]` 和覆盖该范围的连续轨迹段。时间采用本杆累计模拟时间；局部求根得到的 `τ` 必须加上 `ts` 再返回。时间有限且 `0 ≤ ta ≤ tb`，各段完整覆盖范围、边界连续，半径始终有限且大于零。

查询开始先验证数据。缺段、时间倒序、不连续状态、非法半径或不支持的轨迹不能返回普通“未命中”。结果区分“有效且无候选”“有效且有候选”“输入无效或求解未完成”；诊断与字段复用工程已有类型，不强制新建多个结果类。

有候选时返回目标类型、最早本杆时间 `tHit`，以及由原轨迹在该时刻查询的球心、真实半径与速度。该速度用于核查候选状态，此处不归零；真正停球在 5-C。结果可由 Session 装配球状态，但必须使用同一个时间与同一份轨迹。

检查闭区间两端；`ta = tb` 时退化为一次静态查询。查询起点已达成则直接返回 `ta`，不能为了避免重复而偏移时间。相邻段的共享端点使用相同状态，Session 后续负责一次提交，不能把端点漏掉。

## 5. 求出目标有效时间集合

### 5.1 内切：三边条件取交集

每条边继续使用朝内单位法线：`di(t) = dot(ni, C(t) - Vi)`。同时满足以下条件的时间才有效：

`di(t) ≥ 0`，并且 `-T ≤ di(t) - r(t) ≤ T`，三条边均成立。

球心内部检查与贴合容差的区别沿用 5-A2，不把玩法容差用于允许外部球心。每段内 `di-r` 至多二次；求 `di=0`、`di-r=-T`、`di-r=T` 的边界根，再确定各条件成立的区间或孤立时刻。

将三条边的有效时间集合取交集，得到该段内切成立的时间集合。不能把每条边分别“曾经贴合”当成三条边同时成立，也不能只求接近内心的时间。

### 5.2 外接：三顶点条件取交集

对每个顶点令 `Qi(t) = |C(t)-Vi|²`，使用与静态规则等价的条件：

`max(0, r(t)-T)² ≤ Qi(t) ≤ (r(t)+T)²`。

半径小于容差时，下界为零，不能直接使用负下界的平方；若 `r(t)=T` 在段内发生，先在这里为外接求解细分。不要给这种数学分段增加游戏状态或组件。

二次位置平方后至多四次，线性半径平方至多二次，因此边界条件至多为四次多项式。求各顶点上下界的全部实根并保留区间内部分，再确定条件成立的时间集合；三顶点取交集，得到外接成立的时间集合。

下界为零时 `Qi≥0` 恒成立，无须为该下界求根。外接不限制球心必须在三角形内部。只求一个顶点的交点、只检查圆覆盖三角形，均不满足此规则。

### 5.3 完整分割后判断

对一段收集各条件全部边界根和段端点，排序形成分割。分别检查每个分割点及相邻点之间的开区间；在已确认没有遗漏根的开区间内，取内部一点即可确定连续多项式不等式的符号。这是根分割后的判断，不是按固定次数采样轨迹。

保留满足全部条件的闭区间与孤立点，选最早有效时刻；按时间顺序查询轨迹段。分别求内切和外接候选，选择较早者；同一时刻都成立则固定内切优先。

## 6. 求根、数值精度与复核

优先复用已验证的求根工具。没有时，内部求根只覆盖本模型需要的零至四次多项式：常量直接判断、一次与二次直接处理；较高次数可递归求导数实根，将区间分为单调段，在异号段细化根，并单独检查端点和导数根处的重根。恒零多项式代表整段条件边界，不应被当作没有根而遗漏。

不能只对整个区间的两端检查符号变化，或只从一个初值迭代一次；相切重根两侧可能同号。Brent 法要求连续函数在括区间两端异号，因此它可用于已隔离的异号根细化，不能独自发现全部根。该边界参考 [SciPy 官方 brentq 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.brentq.html)。

多重根更敏感，直接取得近似根后仍需残差与原规则复核；这一数值风险也见 [NumPy 官方 polyroots 文档](https://numpy.org/doc/stable/reference/generated/numpy.polynomial.polynomial.polyroots.html)。这两份资料只作为方法参考，不给 Unity 引入 Python、SciPy 或 NumPy 运行依赖。

求解可使用双精度中间值，将局部时间归一到有界范围，控制系数尺度、根残差和时间误差。长度精度、平方长度残差与时间精度分别处理，不共用一个无单位误差，也不扩大 `FitTolerance` 掩盖计算问题。

相近根必须确认是同一个根后才合并，不能仅因时间差小就删除窄小有效区间。比较两个事件时间时，精度尚不足以判断先后应继续细化；不能把先后事件随意归为同刻并用优先级覆盖。

候选必须落在查询范围内，并以原轨迹和 5-A2 静态规则复核。复核未通过时继续细化有效边界，不把时刻挪到区间外、候选之前或无依据的区间中点。若达到迭代或资源限制仍无法确认，返回求解未完成，由调用方保留原状态并诊断，不能静默当作未命中继续提交整个区间。

## 7. Session 的查询范围与事件比较

正式查询只在有效出杆的模拟过程进行。应用本杆起始半径后检查 `t=0`；待机展示、暂停或已经结束的本局不自动查询通关。暂停期间不推进模拟时间。

Session 使用最早出界时刻限制有效查询；已出界的球不能因后续经过目标而成功。如果原运动已有边界检测则复用，并确保检查完整球体。矩形桌面可按四个边界余量 `Cx-r-xMin`、`xMax-Cx-r`、`Cy-r-yMin`、`yMax-Cy-r` 找到进入越界区域的时刻；这部分属于本局边界协调，不混入目标几何。

接触边界但没有进入越界区域时不能仅因余量等于零判出界；出杆初始球体已越界则出界时间为零。边界事件沿用项目规则，并复核半径变化导致的出界，不能只检测球心。

候选按最早时刻选择；同刻优先级沿用“出界 → 目标 → 道具 → 自然停止”。本步实际比较出界、目标和自然停止，道具只保留后续接入约定。目标与自然停止同刻时目标优先，停止终点仍需检查。

查询快照属于某一局、某一杆及该杆的当前轨迹。复位、退出、开始新杆后旧候选作废；当前同步查询无需为此建立额外异步任务或管理器。5-B 的开发验证只检查候选与排序，5-C 再把比较结果接入正式状态提交。

## 8. 固定轨迹验收

以下是规则验收数据，不是关卡默认值。继续使用三角形 `(0,0)、(6,0)、(0,8)`。默认 `T=0.05`，查询 `t∈[0,1]`。

| 场景 | 轨迹或检查方式 | 预期 |
|---|---|---|
| 内切短暂经过 | `C(t)=(1+2t-0.5t², 2), r=2` | 两端未达成；有效窗口为 `[2-√2.1, 2-√1.9]`，最早约 `0.550862325` 秒 |
| 内切零容差瞬间 | 同上，但 `T=0` | 只在 `t=2-√2≈0.585786438` 达成，孤立时刻不能遗漏 |
| 外接零容差瞬间 | `C(t)=(2+2t-0.5t², 4), r=5, T=0` | 同样在 `t=2-√2` 首次外接，两端均未达成 |
| 起点已经达成 | 从正确内切或外接状态开始查询 | 返回查询起点；Session 仍需处理同刻出界优先级 |
| 自然停止端点 | `C(t)=(1+2t-t², 2), r=2, T=0`，`t=1` 停止 | 在终点达成，包含端点和重根，不延伸停止后的轨迹 |
| 分割方式一致 | 第一条轨迹分别整段查询，以及分为 `[0,0.5]`、`[0.5,1]` 查询 | 最早时间、类型、位置与半径在数值精度内一致 |
| 出界先发生 | 对已知目标候选，令有效桌面边界更早被整个球越过 | Session 不返回可通关结果；同刻也由出界优先 |

还需检查半径到上限/下限、`r=T` 外接分段、查询终点恰好达成、零长度区间，以及内切与外接先后不同时选择最早者。恒定半径合法；现有模拟支持的线性增长、缩小和恒定段都应覆盖，不用另造第二套半径模型。

内部求根用 `(u-0.5)²` 检查不变号重根，用恒零/非零常量检查退化处理，用相近但不同的根检查窄区间保留。它们是数值工具验收，不代表新增游戏运动方式。

同一已确认轨迹在 30、60、144 帧显示及不同模拟查询分割下，结果应一致；仅记录一次候选并不能替代 5-C 的一次提交验证。无目标、非法输入、求解未完成与重复查询也要分别检查，查询不能改变任何已提交球状态。

## 9. 制作顺序与下一步

按“只读轨迹与分段 → 内切时间集合 → 外接时间集合及重根 → Session 候选复核与事件比较”逐项制作，每项通过后再继续。数学方法仍集中在 GoalJudge，模拟组件仅提供自身运动与半径数据，不因求解步骤细分多个玩法组件。

5-B 通过标准是：途中短暂贴合与孤立命中不漏判，候选时间最早且可用静态规则复核，分段与显示帧率不改变结果，非法或未完成查询不会伪装成未命中，已出界事件不会被目标覆盖。
