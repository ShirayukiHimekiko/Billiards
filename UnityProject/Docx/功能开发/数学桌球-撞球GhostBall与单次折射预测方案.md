# 数学桌球：撞球 Ghost Ball 与单次折射预测方案

- 日期：2026-10-08
- 任务等级：L3（预测碰撞语义、路径数据与网格表现跨文件功能）
- 状态：用户已确认并完成代码实施；尚未运行编译、测试或 Unity
- 规范：已读取仓库与 `UnityProject` 的 `AGENTS.md`、`tengine-dev` 相关规范、`game-developer` Unity 开发规范

## 1. 已确认的表现规则

### 1.1 未撞到球

- 预测虚线继续表示白球球心轨迹。
- 图形和道具不会中断预测线，也不生成空心圆或出射方向线。
- 白球进入球洞时不生成碰撞圆，保留现有落袋预测语义。

### 1.2 撞到库边

- 未启用“折射预测”道具时，线路在第一次撞库处终止显示，继续显示现有的白球空心轮廓。
- 启用“折射预测”道具时，最多额外显示第一次撞库后的一段反射轨迹。
- 该反射轨迹如果遇到第二面库边，在第二次撞库位置显示白球空心轮廓，但不继续显示第二次反射后的线路。
- 所有撞库圆继续使用撞库瞬间的白球实际半径，不使用静止时半径或固定半径。

### 1.3 撞到其他球

- 无论被撞对象是当前黑球还是未来新增的其他球类，均按球体碰撞处理，不对 `BallKind` 写特例分支。
- 白球入射虚线终点为碰撞瞬间的白球球心，不再延伸到被撞球的球面接触点。
- 在该球心位置绘制与碰撞瞬间白球实际半径一致的空心圆，即 Ghost Ball。
- 白球轨迹在这次球体碰撞处终止显示；即使启用“折射预测”道具，也不显示白球撞球后的偏转轨迹。
- 从被撞球的球心开始，沿其碰撞响应后的真实速度方向绘制一段实线。
- 出射线长度为被撞球碰撞瞬间的一个直径；该长度不随力度改变，只表达出射方向，不冒充完整运动距离。
- 出射线复用现有预测线颜色与线宽，不新增材质、Prefab 或独立 `LineRenderer`。

### 1.4 显示信息边界

- 球体碰撞发生在当前可见分段时，才显示 Ghost Ball 和目标球出射线。
- 未启用折射道具时，第一次撞库后的球体碰撞不应透露出来。
- 启用折射道具时，可显示第一次撞库后遇到的球体碰撞；第二次撞库后的信息仍不显示。

## 2. 现状与问题

当前实现已经具备可复用的精确基础：

- `PhysicsWorld.Predict` 复制全桌状态，预测和正式出杆共用同一套连续事件求解、碰撞冲量和变半径规则。
- `PhysicsWorld.Step` 可在精确碰撞时刻取得两球球心、半径及响应后速度。
- `PredictionPath` 已使用可复用的分段与撞库接触缓存，没有逐帧创建显示对象。
- `GeometryGraphic` 已经把预测虚线和撞库圆绘制到同一个运行时网格。
- `BoardView` 通过最大可见分段数限制玩家可看到的预测信息。

当前不符合新规则的部分是：

1. 球体碰撞时，入射分段会被延长到被撞球表面，而不是停在白球碰撞瞬间的球心。
2. 球体碰撞后会为白球创建新分段，折射道具启用时可继续显示白球偏转轨迹。
3. 预测结果没有保存球体碰撞事件的显示语义，表现层无法绘制 Ghost Ball 和被撞球出射方向。
4. 折射道具当前使用 `int.MaxValue` 显示所有后续分段，不符合“只折射一次”。

## 3. 方案设计

### 3.1 预测结果记录球体碰撞事件

在 `PredictionPath` 中增加可复用的球体碰撞显示记录，最小数据包含：

- 碰撞瞬间的白球球心与半径；
- 被撞球球心与半径；
- 经过现有冲量求解后的被撞球出射单位方向；
- 该碰撞所属的白球预测分段索引。

记录使用 `List<T>.Clear()` 与现有容量复用模式，不在鼠标移动或蓄力刷新路径中创建 GameObject、材质或临时集合。

### 3.2 球体碰撞与白球显示终止

`PhysicsWorld` 仍然继续运行完整的预测副本，不改变正式物理、规则事件或预测完成判定。只终止白球的可见轨迹收集：

1. 推进至球体精确接触时刻。
2. 把白球当时的真实球心追加为当前分段终点，并保证虚线在该终点可见。
3. 执行现有 `Resolve` 球体冲量响应。
4. 从响应后的被撞球状态取出速度方向，写入球体碰撞显示记录。
5. 结束当前白球显示分段，不因该球体碰撞创建白球后续分段，也不记录后续球体碰撞。

这个边界使“物理仍完整预测”与“玩家只看到第一次球体碰撞”同时成立，不会为显示要求修改碰撞公式。

### 3.3 Ghost Ball 与目标球出射线

`GeometryGraphic` 在现有预测网格中追加：

- 以白球碰撞球心为圆心、当时实际半径为半径的空心圆；
- 以被撞球球心为起点、响应后速度单位方向为方向、被撞球直径为长度的实线。

Ghost Ball 复用现有 32 段空心圆绘制方式。出射线直接复用现有线段网格构建方法，不受虚线 dash/gap 相位影响，避免一个球直径的短线恰好落在虚线间隙中。

### 3.4 最多一次折射

`BoardView` 的可见分段上限改为：

- 折射道具未启用：`1` 段；
- 折射道具已启用：`2` 段。

这两段分别是第一次撞库前的入射段和第一次撞库后的反射段。第二次撞库接触圆属于第二段的末端，因此仍会显示；第二次撞库后的第三段不显示。

当预测真实终点位于隐藏分段时，继续隐藏实心终点圆点，避免玩家把隐藏路径的终点误解为当前线段终点。球体碰撞已由 Ghost Ball 表达，该位置不再叠加实心终点圆点。

## 4. 预计修改范围

### 4.1 `Core/Physics/PredictionPath.cs`

- 新增球体碰撞显示记录及可复用缓存。
- 记录球体碰撞是否已终止白球显示路径。
- 保留现有分段、撞库接触和真实预测终点语义。

### 4.2 `Core/Physics/PhysicsWorld.cs`

- 球体碰撞前记录 Ghost Ball 圆心和半径。
- 球体碰撞响应后记录被撞球真实出射方向。
- 取消白球入射线向被撞球表面的显示延伸。
- 球体碰撞后不再创建白球可见后续分段。
- 不修改 `Resolve` 的冲量、质量、恢复系数、数值分离或正式模拟逻辑。

### 4.3 `Core/Level/GeometryGraphic.cs`

- 按可见分段过滤球体碰撞记录。
- 绘制 Ghost Ball 空心圆和被撞球实线出射指示。
- 继续复用现有顶点、颜色和索引缓存。

### 4.4 `Core/Level/BoardView.cs`

- 将折射道具启用时的可见分段上限从无限改为两段。
- 在球体碰撞终止显示时不叠加实心预测终点。
- 保留现有方向、力度和世界版本缓存策略。

### 4.5 不在范围内

- 不修改 `Module/UIModule/`、`UI/` 或 `UI/Gen/`。
- 不修改 Luban 源表、生成代码、物理参数或球类枚举。
- 不新增第三方依赖、Prefab、材质、Shader 或独立场景对象。
- 不实现目标球的完整停球轨迹、多级球体连锁轨迹或自动吸附瞄准。

## 5. 设计原则与参考结论

- **单一职责**：`PhysicsWorld` 输出精确碰撞事实，`PredictionPath` 承载可见预测语义，`GeometryGraphic` 只负责绘制。
- **开闭原则**：在现有预测结果中扩展球体接触记录，不替换共用物理求解器。
- **合成复用**：继续复用全桌预测副本和网格缓存，不创建第二套近似射线或 Unity Rigidbody 预测。
- **接口隔离**：球体碰撞显示记录只包含绘制所需的数据，不向表现层暴露可变世界状态。
- GitHub 的 Unity 台球轨迹示例普遍通过隔离物理副本收集轨迹。本项目已有更适合变半径、道具和规则事件的确定性连续求解，因此只借鉴“预测与正式模拟共用规则”，不引入外部实现。

## 6. 边界情况

1. **直接撞球**：显示入射虚线、Ghost Ball 和目标球短实线；不显示白球后续线。
2. **第一次撞库后撞球**：只在折射道具启用时显示反射段及该次球体碰撞提示。
3. **第二次撞库**：道具启用时显示第二次撞库圆，不显示其后的线。
4. **球洞**：不生成空心碰撞圆；不把球洞当作球体处理。
5. **图形与道具**：不生成空心圆或出射线，并保留当前预测线忽略几何门阻挡的既有例外规则。
6. **未来新球类**：只要参与 `EventKind.Ball` 碰撞，自动获得相同显示，无需修改表现分支。
7. **极小出射速度**：仅在已有物理停球阈值认定方向有效时绘制出射线，不对零向量归一化。

## 7. 实施顺序

1. 扩展 `PredictionPath` 的球体碰撞显示数据与缓存。
2. 调整 `PhysicsWorld` 的预测轨迹收集，在现有冲量响应前后记录所需数据，撞球后终止白球可见路径。
3. 扩展 `GeometryGraphic` 的同网格绘制，加入 Ghost Ball 与目标球短实线。
4. 把 `BoardView` 的道具可见范围改为最多两段，并修正终点圆点显示条件。
5. 更新本文档的实施记录并汇报变更。

## 8. 建议的后续检查（仅在用户明确要求时执行）

- 正撞、斜撞与近切撞时，Ghost Ball 圆心和半径是否与实际接触一致。
- 目标球短线是否从球心开始，并与实际出射方向一致。
- 未启用折射道具时，第一次撞库后的所有信息是否隐藏。
- 启用折射道具时，第二次撞库圆是否显示，第三段轨迹是否隐藏。
- 直接撞球或第一次反射后撞球时，白球是否都不再显示后续偏转线。
- 球洞、图形和道具是否不会误生成碰撞圆或目标球出射线。
- 蓄力和鼠标移动持续刷新预测时，是否没有新的逐帧 GC 分配。

本方案不主动运行编译、测试或 Unity 场景；实施后依项目规则询问用户是否需要检查。
