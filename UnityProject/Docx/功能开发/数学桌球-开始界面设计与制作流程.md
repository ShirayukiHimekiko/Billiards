# 数学桌球：开始界面设计与制作流程

日期：2026-10-05 · 版本：v0.1 · 任务等级：L3

> 后续需求更新（2026-10-06）：开始按钮关闭开始界面并打开主界面；退出按钮退出应用；设置打开非全屏弹窗，仅调整现有四类音量；存档、制作详情暂不实现。开始与主界面均全屏。详见[按钮设计](数学桌球-开始与退出按钮功能设计.md)和[设置设计](数学桌球-设置界面与四类音量设计.md)。本文的“本阶段”保留首阶段美术与静态界面制作记录，后续功能以更新文档为准。

## 1. 本次需求与交付边界

先制作文档，再制作开始界面的 UI 图片，随后按文档搭建静态开始界面，下一步再编写按钮功能。菜单包含五个按钮，顺序为：**开始、设置、存档、制作详情、退出**。本次交付设计文档、界面效果图、无文字背景及可复用按钮底图；Unity 中的界面搭建作为后续执行步骤，本文不代表 Prefab 已完成。

本阶段的按钮只呈现入口及视觉状态，不绑定点击业务，不进入关卡、不打开设置或存档页面、不读写文件、不弹出制作详情、不退出应用。开始按钮也不能沿用已有测试入口自动进入游戏。

## 2. 设计依据与现有项目状态

- 游戏为俯视击球解谜：通过方向、力量和白球尺寸变化，达成三角形的内切或外接目标。
- 沿用现有像素资源 v0.1：深蓝桌面、胡桃木边框、象牙白球、青色变化提示、金色几何目标、紫色翻转道具。不会加入球袋、黑8、对手或排行榜等尚未设计的玩法。
- 已有 `button_normal.png`、`button_pressed.png` 可复用，按钮文字与图片分离。
- 实际热更入口 `GameApp.StartGameLogic()` 目前未打开业务窗口，`GameEventHelper.Init()` 也处于注释状态；后续搭建应核查启动链，不能假定主菜单或事件桥接已经存在。
- 已存在 `Assets/AssetRaw/UI/MainUI.prefab`，后续搭建前先检查用途和绑定，不直接覆盖。开始窗口命名为 `StartUI`；主界面类名为 `MainUI`，新资源地址暂定 `GameMainUI`，详见核心入口文档。
- 本方案补充旧文档第八步的“简单入口”，作为新的启动主菜单；旧文档的关卡内“退出”仍表示清理本局并返回入口。

依据：项目 `tengine-dev` 的 UI 生命周期、命名、资源 API 与热更工作流规范；实际 `GameApp.cs`、`WindowAttribute.cs`；现有玩法说明与美术使用说明。

## 3. 开始界面布局

基准画布为 **1280×720，横屏**。下表坐标以画布左上角为原点，供后续 RectTransform 换算；不直接当作 Unity 的 anchoredPosition。

| 内容 | 建议矩形（x, y, 宽, 高） | 说明 |
|---|---|---|
| 背景 | 0, 0, 1280, 720 | 满屏深蓝像素桌面，四周木质边框 |
| 标题“数学桌球” | 112, 100, 360, 72 | 象牙白或浅金，字号约 56 |
| 开始 | 128, 238, 304, 64 | 主入口，金色轮廓更醒目，字号约 30 |
| 设置 | 128, 326, 304, 52 | 次级按钮，字号约 24 |
| 存档 | 128, 398, 304, 52 | 与设置同规格 |
| 制作详情 | 128, 470, 304, 52 | 保留完整四字文案 |
| 退出 | 128, 542, 304, 52 | 位置最下方，普通次级样式 |
| 主题插画区域 | 600, 156, 520, 420 | 白球、金色三角形、青色辅助圆、紫色道具 |

按钮垂直排布，主按钮与次按钮间隔 24，次按钮间隔 20。所有按钮保留至少 48 个基准像素的高度。背景右侧主题插画仅为装饰，没有碰撞体、输入或通关判定。

```text

│                                                      │

│                                                      │
```

效果图用于确认视觉方向；后续可编辑 UI 的位置、按钮数量、中文文案和字体以本文为准。不要把整张效果图当成最终可交互界面。

## 5. 制作顺序与阶段划分

### 阶段 A：文档与图片（本次）

1. 保存本设计文档，确定五个按钮、布局、风格及阶段边界。
2. 生成无文字主题背景，再制作带标题和五个按钮的静态效果图。
3. 复用现有常态与按下按钮底图，整理独立资源、完整提示词及清单。
4. 检查文件可解码、透明通道、尺寸、文案及效果图。记录完成状态；不把静态图描述为 Unity 运行结果。

### 阶段 B：搭建静态 Unity 开始界面（后续执行）

1. 使用 `unity-pipeline` 技能，发现目标 Editor 和实际命令，检查当前未保存内容、已有 Canvas、`MainUI.prefab` 与资源收集配置。
2. 按冲突检查结果导入本次独立图片。目标建议为 `Assets/AssetRaw/UIRaw/Raw/MathBilliards/StartMenu/`；导入、GUID 和 Importer 设置均通过 Pipeline 处理。
3. 复用项目 Canvas 与 UI 框架，创建独立 `StartUI.prefab`，建议位于 `Assets/AssetRaw/UI/Billiards/`，确认 YooAsset 实际收集覆盖及资源地址唯一性。
4. 使用独立 Image、Button、文字组件搭建标题与五个按钮。所有 Button 的持久化 `OnClick` 列表为空，不添加运行时业务回调。允许内置按下变色或 Sprite Swap 反馈。
5. 如需窗口外壳，按[当前脚本目录约定](../架构设计/数学桌球-脚本目录归属约定.md)沿用热更域 GameLogic/UI 与实际生成器、Prefab 配置，不预设 UI/Billiards 子目录；窗口继承 `UIWindow`，标记 `[Window(UILayer.UI, "StartUI", fullScreen: true)]`，仅绑定节点与显示。
6. 检查项目真实入口后，通过 `GameModule.UI` 显示窗口，不自动加载桌球会话。遵循已有启动流程，不改动主包和热更边界。
7. 完成资源引用、编译、实际启动显示与多分辨率检查，记录结果。

### 阶段 C：下一步编写按钮功能

| 按钮 | 后续方向 | 本次状态 |
|---|---|---|
| 开始 | 进入桌球关卡；防重复进入，显示加载状态 | 仅设计与视觉入口 |
| 设置 | 打开非全屏 SettingsUI，四项为背景音乐、游戏音效、界面音效、声音 | 最新设计与美术已准备，功能待接入 |
| 存档 | 打开存档界面；新游戏/继续/存读档规则下一步确定 | 仅设计与视觉入口 |
| 制作详情 | 打开制作信息；作者、引擎与资源署名内容下一步提供 | 仅设计与视觉入口 |
| 退出 | 退出应用；Editor 中结束 Play Mode | 功能设计已确定，待接入 |

这些方向不是本次实现任务，不提前建立存档数据结构或占位作者名单。最新约定为开始菜单和关卡内的退出均退出应用。实际接入跨模块事件前恢复并核查 `GameEventHelper.Init()` 的初始化时序。

## 6. 后续 UI 节点约定

```text
StartUI
├── m_img_Background
├── m_rect_SafeArea
│   ├── m_tmp_Title                 数学桌球
│   └── m_rect_Menu
│       ├── m_btn_Start             开始
│       │   └── m_tmp_StartLabel
│       ├── m_btn_Settings          设置
│       │   └── m_tmp_SettingsLabel
│       ├── m_btn_Save              存档
│       │   └── m_tmp_SaveLabel
│       ├── m_btn_Credits           制作详情
│       │   └── m_tmp_CreditsLabel
│       └── m_btn_Exit              退出
│           └── m_tmp_ExitLabel
└── Decoration                     仅需要额外前景装饰时添加
```

`m_tmp_` 对应 TextMeshProUGUI，需确认项目中文字体覆盖，不显示缺字方框。装饰与背景关闭 Raycast Target，按钮为接收输入的主要对象。复用 UIScriptGenerator 生成组件绑定，不手工篡改生成器配置。窗口销毁回调是 `OnDestroy()`；需要加载 Sprite 时使用 `SetSprite`，避免 `Resources.Load` 与手动 Sprite 句柄管理。

## 7. 导入与适配建议（尚未执行）

- Texture Type：Sprite (2D and UI)；Sprite Mode：Single；Filter：Point；Wrap：Clamp；关闭 Mipmap，NPOT 保持原尺寸；透明底图保留 Alpha，无压缩，Read/Write 关闭。
- 背景保持宽高比例，覆盖画布并允许边缘裁切；菜单保持在安全区内，不跟随背景裁切。
- Canvas Scaler 建议 Scale With Screen Size，参考 1280×720，Match 0.5，最终以现有 Canvas 配置及实测为准，不为本菜单改动全局设置。
- 检查 1280×720、1920×1080、1024×768 和 2560×1080。窄画面优先保留全部菜单，右侧主题图可以裁切。竖屏不在本阶段范围。
- 按钮需要按比例保持像素边缘；未测定 9-slice border 前不要随意开启 Sliced，避免边框和纹理拉伸。

## 8. 验收标准

**本次文档与美术：**文档已落盘；五个按钮顺序和文案明确；效果图具备标题与五个按钮；背景没有文字和按钮；可复用底图透明；文件、提示词、来源和尺寸均可查。

**后续静态 Unity 界面：**启动后出现开始界面；五个按钮和中文可读；点击仅有视觉反馈，不启动玩法、不打开业务窗口、不读写存档、不退出程序；没有缺失引用、导入或编译错误；适配检查通过；未保存无关场景。

**验证边界：**本次不修改 C#、Scene、Prefab、Importer 或启动入口，不执行 Unity 导入、编译、Play Mode 或构建。图片与文档检查不等于可运行界面验收。
