## 诊断与处理方案

| 问题 | 原因 | 处理 | 风险 |
| --- | --- | --- | --- |
| 导表后 Tables 为空 | 注册表已清空；内置 Luban 默认关闭自动导入，默认文件名规则不支持下划线 | 客户端导表入口启用自动导入并扩展正则，保留最新 `#` 文件 | 低，使用现有导表工具验证 |
| 关卡表引用旧表 | `ballConfigId` 仍引用 `billiards.TbBall` | 改为 `int#ref=Tbbilliards_ball`，通过 helper 修改源表并重新导出 | 低，Luban 执行关联校验 |
| 配置加载接口与业务脱节 | 源模板恢复同步加载，但业务使用 IsReady/Initialize/Release | 在源模板恢复内存解析接口，异步资源加载留在 GameLogic | 中，涉及跨程序集边界；静态编译检查 |
| 加载旧 bytes 地址 | LevelManager 写死旧手动注册地址 | 由 Tables 模板生成 DataFileNames，按生成地址加载 | 低，地址与输出同源 |
| 向量转换无法编译 | ExternalTypeUtil 引用的五个向量定义缺失 | 补齐 Defines/builtin.xml 并重新生成类型 | 低，不改变关卡标量字段 |
| 改击球次数后提示错误 | 失败消息写死“三杆” | 从关卡 MaxShots 生成提示 | 低 |
| 退出后加载回调继续操作 UI | 异步加载可能晚于模块释放结束 | GameManager 增加退出标记，退出阶段阻止菜单打开和取消回调操作 UI | 中，沿用取消令牌和原清理顺序 |
| 设置界面编译警告 | 私有 Close 隐藏 UIWindow.Close | 回调改名 OnClose，同步更新注册与注销 | 低 |
| 核心代码过度压缩 | 多语句同一行、运算符及缩进不统一、公共方法缺说明 | 规范化目标脚本格式，补全中文 XML 接口说明 | 低，不修改判定数学 |

## 当前配置方式

| 数据源 | 生成类型 | Tables 访问成员 | bytes 资源名 |
| --- | --- | --- | --- |
| Configs/GameConfig/Datas/#billiards_ball.xlsx | GameConfig.Tbbilliards_ball / billiards_ball | TbbilliardsBall | tbbilliards_ball |
| Configs/GameConfig/Datas/#billiards_level.xlsx | GameConfig.Tbbilliards_level / billiards_level | TbbilliardsLevel | tbbilliards_level |

`__tables__.xlsx` 保持空的注册数据区。`#` 文件使用默认 map 模式，首个字段 id 为索引。关卡通过 Luban 生成的 `BallConfigId_Ref` 获取球参数。

Windows 的 `gen_code_bin_to_project.bat` 和 `gen_code_bin_to_project_lazyload.bat` 均使用同一懒加载模板；同名 shell 脚本保持一致。失败时脚本返回错误，AI_MODE 下跳过 pause。业务配置仍归在源 Excel 和模板中，生成的 GameProto 不手动修改。

加载流程：LevelManager 异步加载每个 DataFileNames 对应的 TextAsset，复制字节并在 finally 卸载资源；ConfigSystem 校验数据完整性、持有自己的字节副本并构造 Tables；首次查询表时解析内存。准备或解析失败会释放缓存，再次进入允许重试。GameProto 不依赖 GameLogic 或新增异步程序集。

关闭游戏时保留上一轮修复：先解绑 Runner，再 Release 会话和球体，最后销毁台面；会话 Release 不调用会刷新 Transform 的 Simulation.Stop。BallBase.Release 允许功能组件已经被 Unity 销毁。
