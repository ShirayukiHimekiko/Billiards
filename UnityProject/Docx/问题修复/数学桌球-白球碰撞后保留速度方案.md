# 数学桌球：白球碰撞后保留速度方案

- 日期：2026-10-08
- 任务等级：L2，调整现有球间碰撞规则与配置，不新增物理系统。
- 状态：用户已确认并完成配置实施；未修改碰撞求解代码，未运行编译、测试、关卡回放或 Unity。

## 1. 问题判断

当前实现已经发生了真实球间碰撞，并非代码把白球速度直接赋值给黑球。`PhysicsWorld.Resolve` 使用质量与球间恢复系数计算法向冲量。

现有配置中白球和黑球质量均为 1，`ballRestitution` 为 1。对白球正面撞击静止黑球的情况，等质量、完全弹性碰撞会使白球法向速度变为 0，黑球得到全部法向速度；因此“白球停、黑球继续”是当前参数下的必然结果。

斜碰时白球原有切向速度仍会保留。用户要求的“白球不要停”准确含义应为：正碰后白球仍保留可见的向前速度，同时黑球仍受到碰撞推动。这是玩法规则调整，不是修复漏碰撞。

## 2. GitHub 方案评估

参考项目：

- [tailuge/billiards 的球间碰撞实现](https://github.com/tailuge/billiards/blob/master/src/model/physics/collisionthrow.ts)：继续使用法向冲量，球间恢复系数取 0.925，并额外建模接触摩擦与旋转。
- [tailuge/billiards 项目说明](https://github.com/tailuge/billiards)：公开说明其法向冲量仍由恢复系数参与计算。
- [walidargh/Billiards](https://github.com/walidargh/Billiards)：手写物理引擎使用球间恢复系数 0.95。

这些项目支持“保留冲量模型、通过恢复系数描述能量损失”的方向，不支持碰撞后强行给白球补速度。后者会凭空增加动量或能量，还可能造成接触面重复碰撞。

外部示例的 0.925～0.95 偏向真实台球；对本项目等质量正碰，白球只会保留约 2.5%～3.75% 的入射法向速度，在当前恒定减速度和停球阈值下可能仍不够明显。具体数值属于玩法手感，不应机械照抄。

## 3. 推荐方案

保留现有碰撞检测、冲量公式、质量配置和预测共用物理世界，只调整现有 `ballRestitution`：

1. 将 `Physics.xlsx` 的 `ballRestitution` 从 1 调为 0.6。
2. 同步修改 `UnityProject/Tools/ConfigureGameConfig.py` 中的同一作者数据，避免以后重跑工具把参数覆盖回 1。
3. 按现有 Luban 流程重新导出 `tbphysics.bytes`，不手工修改生成 C# 或二进制文件。
4. 不添加碰撞后的最小速度、额外推力或白球专属速度覆盖；这些做法会破坏守恒关系并引入低速抖动风险。
5. 预测与实际运动都使用 `PhysicsWorld`，因此无需另改预测公式。

对等质量、静止黑球的正碰，恢复系数为 0.6 时：

- 白球保留约 20% 的入射法向速度；
- 黑球获得约 80% 的入射法向速度；
- 两球碰撞后继续分离，不会把同一份速度重复赋给两球。

这能让“白球不立即停下”有可见效果。若希望更接近真实台球，可改为 0.8～0.925，但白球只保留约 10%～3.75% 的法向速度，视觉效果会更弱。

## 4. 影响与边界

- `ballRestitution` 是全局球间参数，黑球之间的碰撞也会同步损失更多动能；如果只允许白球撞黑球时生效，就需要新增成对恢复系数字段和求解分支，属于更大的配置与代码改动，本轮不优先推荐。
- 临近自然停球时，碰撞后的白球速度仍可能低于 `stopSpeed` 而停止。若要求任何微小碰撞后都永不立即停球，就必须改变停球规则，会带来长尾运动与抖动，不建议混入本次需求。
- 物理参数变化可能改变多球连锁、进洞时序及既有二十关参考解。实施后是否做关卡回放、编译或 Unity 试玩，按用户后续明确要求执行。
- 本方案不引入第三方依赖，不改变 `PhysicsWorld.Resolve` 职责，也不新增不必要的策略类或接口。
