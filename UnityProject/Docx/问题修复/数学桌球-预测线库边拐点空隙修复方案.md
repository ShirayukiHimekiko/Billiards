# 数学桌球：预测线库边拐点空隙修复方案

- 日期：2026-10-07
- 任务等级：L3（预测数据语义与虚线表现的跨文件局部修复）
- 状态：用户已确认并完成代码实施；尚未运行编译、测试或 Unity

## 1. 问题判断

截图中的三个库边反射位置都有明显空白，但需要区分两种距离：

1. 预测路径记录的是白球球心轨迹。球体接触库边时，球心必然与边界保持一个当前球半径，因此轨迹拐点不会落到可见木质边框上。这是物理语义，不是漏算。
2. 当前虚线相位跨预测分段连续分配。库边反射会结束旧分段并开始新分段，但旧分段没有标记“末端必须可见”，新分段也没有标记“起点必须可见”。当反射点恰好处于 dash/gap 的 gap 区间时，拐点两侧都可能没有实线。该空白再叠加球半径偏移，就形成截图中的大段断口。

现有实现已经对球碰撞终点调用 `DrawVisibleEnd`，避免球面接触点落在虚线间隙中；库边反射没有对应处理，行为不一致。

## 2. GitHub 方案调研与适配

参考：

- [Unity UI Extensions](https://github.com/Unity-UI-Extensions/com.unity.uiextensions)：成熟的 Unity 线条网格实现会把线段连接、端帽和折角作为独立几何职责处理，不能只依赖虚线纹理或周期相位恰好覆盖折点。
- [Unity custom UI Line Renderer with dash support](https://gist.github.com/SinanErmis/850b907064d5a800ed5e08daaf2b8b9d)：其虚线实现显式判断折角是否可见，并为相邻线段保留端部结构，说明折点可见性需要单独处理。
- [unity-billiards-trajectory](https://github.com/vonWolfehaus/unity-billiards-trajectory)：适合参考“预测沿真实模拟轨迹采样”的职责边界，但不直接引入其 Rigidbody/PhysicsScene 方案。本项目已有连续事件物理与可复用预测分段，替换物理系统成本过高且不能直接解决虚线拐点空白。

上述实现不直接复制。当前项目已经用 `GeometryGraphic` 构建无额外对象分配的运行时网格，最合适的是补齐拐点可见语义，而不是引入第三方组件、Shader 或第二套轨迹系统。

## 3. 推荐方案

### 3.1 显式记录库边反射接缝

- 为预测分段增加“起点必须可见”的显示语义；沿用现有“末端必须可见”语义。
- 白球发生库边反射时：旧分段末端标记为必须可见，新分段起点标记为必须可见。
- 球碰撞仍只保证入射段的球面接触终点可见；碰撞后的白球圆心分段不与球面接触点强行连接。
- 预测忽略几何门的既有规则保持不变，不扩大本轮范围。

### 3.2 在拐点两侧补最短可见线段

- `GeometryGraphic` 保留现有全局 dash/gap 相位，正常虚线节奏不重置。
- 对标记的库边接缝，在入射段末尾与反射段开头分别叠加一段长度不超过单个 dash 的实线。
- 两段实线共用真实反射接缝位置，使 V 形折点连续可读；短轨迹按实际段长裁剪，不向路径外延伸。
- 继续复用当前顶点、颜色和索引缓存，不创建 GameObject，不在每帧引入新的集合或材质实例。

### 3.3 保留球心轨迹语义

- 不把拐点强制移动到木质边框。那会把球当作半径为零的点，导致预测辅助线与实际球体首次碰撞位置不一致。
- 不修改 `ContactSolver.Plane`、反射法线、恢复系数、球半径或台面 Bounds。
- 不通过减小 `GapLength` 掩盖问题；全局缩短间隔会改变整条预测线样式，却不能从语义上保证每个反射拐点可见。

## 4. 预计修改范围

1. `Core/Physics/PredictionPath.cs`：增加分段起点可见标记及最小接口。
2. `Core/Physics/PhysicsWorld.cs`：库边反射分段时写入接缝可见语义，不改变正式模拟。
3. `Core/Level/GeometryGraphic.cs`：增加起点补线逻辑，沿用现有末端补线与网格缓存。

不修改 Prefab、材质、Shader、Luban 表、物理参数和关卡资源。

## 5. 设计原则与风险

- 单一职责：物理世界只报告反射事件语义；绘制组件负责 dash/gap 和局部可见补线。
- 开闭原则：扩展预测分段的显示标记，不改写通用接触求解与反射公式。
- 合成复用：继续复用现有 `PredictionPath`、`GeometryGraphic` 和缓存列表，不引入新渲染体系。
- 风险：补线会在反射点附近局部增加实线密度，这是“保证碰撞点可读”的刻意表现。补线长度限制为一个 dash，避免把大范围虚线变成实线。
- 边界：轨迹仍与可见库边保持当前球半径。如果需求其实是让虚线字面触碰边框，则需要另做“零半径辅助射线”的显示模式，并接受它与真实球心轨迹不一致；本方案不建议这样处理。
