# 数学桌球：瞄准范围扩大与蓄力跟随方案

日期：2026-10-07
状态：用户已确认，功能代码已修改；尚未运行验证
任务等级：L3（输入与台面投影的跨文件局部修改）

## 当前原因

- BilliardsBoardView.ScreenPoint 同时判断相机视口和台面 Bounds，输入将这个结果直接作为预测线显示条件，鼠标移到桌面外时预测被隐藏。
- BallShootComponent.Update 用 !Charging 限制方向更新，所以按住左键蓄力时方向被锁定。
- 目前开始蓄力及松开出杆都要求鼠标在桌面内且未覆盖 UI。

## 建议行为

1. 瞄准区域扩大到整个游戏画面（世界相机 pixelRect）。桌面外的鼠标仍可投影到台面平面，更新白球至鼠标的方向及反射预测。
2. 出杆区域继续限定为实际台面 Bounds，不能在桌面外或 UI 上按下开始蓄力。
3. 延续现有松开规则：必须在桌面内且不覆盖 UI 时松开才能出杆；桌外/UI/游戏画面外松开取消本次蓄力，不消耗机会。蓄力时可以移到桌外瞄准，并移回桌面松开。
4. 蓄力期间每帧更新方向，释放时采用最新鼠标方向与力度。白球真正发射以后仍按该杆物理轨迹运动，鼠标不操控已发射的球。
5. 鼠标恰好位于白球中心时保留最后有效方向，防止零向量；鼠标不在游戏画面时隐藏瞄准反馈。
6. 保留右键取消、Esc/失焦暂停及 UI 点击拦截。瞄准跟随不改变杆数、球洞、道具或几何规则。

## 实现范围

- BilliardsBoardView：拆分屏幕投影和台面区域判断，分别提供有效瞄准坐标和是否位于桌面。
- BallShootComponent：使用两个独立判断控制预测与出杆；去除蓄力锁定方向；调整每帧处理顺序，使预测使用本帧方向与力度。
- 不增加管理器、Prefab 字段或关卡表；瞄准范围来自当前相机视口，发射边界复用台面表 Bounds。

## 实施结果

- BilliardsBoardView.TryProjectScreenPoint 只处理相机视口与平面投影；IsOnTable 独立检查配置中的台面 Bounds。
- BallShootComponent 使用 canAim 显示预测，使用 canShoot 控制按下和松开；蓄力状态不再锁定鼠标方向。
- 本帧输入和蓄力更新后再刷新瞄准反馈；成功出杆立即隐藏预测，取消蓄力后显示零蓄力对应的预测。
- 桌外按下不能启动蓄力，桌外或 UI 上松开取消；桌外仍可瞄准，不消耗击球次数。
- 没有新增配置字段、Prefab 或管理器，没有修改球运动、球洞和道具规则。
