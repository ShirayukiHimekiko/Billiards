# 数学桌球：图形达成后停球并进入下一杆方案

日期：2026-10-08 · 任务等级：L3 · 状态：用户已确认，代码修改已完成，未运行验证

## 1. 需求解释

白球在运动过程中首次成功满足图形配置的内切或外接条件后，不再穿过图形继续运动，而是停在该图形对应目标圆的标准状态，随后按现有回合规则进入下一杆。

本方案中的“通过图形”指 `GoalJudge` 已确认内切或外接成立，不是球刚进入三角形、接触条件圆或被几何门放行。不能达成条件的接近仍按现有目标圆碰撞规则反弹。

“停在图形中间，内切或外接的位置”解释为：

- 球心提交为 `GeometryData.Center`；
- 球半径提交为 `GeometryData.Radius`；
- 球速度归零，当前杆不再继续改变白球位置或大小；
- 内切与外接共用同一处理流程，圆心和半径继续由现有三角形数据计算，不增加重复配置。

## 2. 当前源码事实

- `GoalJudge.FindGoal()` 已对连续轨迹求解，并返回当前轨迹片段内首次满足内切／外接条件的精确时刻。
- `PhysicsWorld.Step()` 会先将全部球推进到该事件时刻，再调用 `Resolve()` 处理 `EventKind.Goal`，因此无需新增 Trigger、Collider2D、逐帧距离轮询或第二套物理体系。
- 当前 `Resolve(EventKind.Goal)` 只提交图形效果和完成状态，没有停止白球，所以白球会继续消耗该固定步剩余时间并向前运动。
- `Session.Tick()` 已在 `World.Moving == false` 时调用 `FinishShot()`，恢复 `Ready` 或进入胜负结算；无需另建回合状态或额外事件。
- 当前规则要求全桌活动球停止后才能进入下一杆。白球命中图形后归零，但已经运动的黑球仍应完成当前物理过程，之后再开放下一杆。

以上结论来自源码阅读，尚未通过编译、测试或 Unity 运行验证。

## 3. GitHub 成熟方案评估

参考 [Box2D 的连续碰撞与 Time of Impact 说明](https://github.com/erincatto/box2d/blob/main/docs/collision.md)及[模拟流程说明](https://github.com/erincatto/box2d/blob/main/docs/simulation.md)：连续事件应先求出首次事件时刻，将物体推进到该时刻，再执行响应，避免高速运动穿越目标。

本项目现有 `GoalJudge` 与 `PhysicsWorld` 已采用同类的“求最早时刻 → 推进到事件点 → 响应”结构，因此继续扩展现有 `Goal` 响应即可。不会引入 Box2D、Rigidbody2D 或第三方桌球项目，避免与当前变半径、确定性连续轨迹模拟形成双重运动来源。

## 4. 建议实施方案

修改范围集中在 `Assets/GameScripts/HotFix/GameLogic/Core/Physics/PhysicsWorld.cs`：

1. 在 `Resolve(EventKind.Goal)` 完成现有解锁球洞／触发道具逻辑后，仅对白球提交目标圆标准状态。
2. 将白球位置设置为当前 `GeometryData.Center`，半径设置为 `GeometryData.Radius`，速度设置为 `Vector2.zero`。
3. 不重置出生位置，不清除图形、球洞、道具或进球进度；下一杆继续使用该停球位置和半径。
4. 不直接修改 `Session` 状态。若此时没有其他运动球，现有 `World.Moving` 会立即变为 `false`，`Session.FinishShot()` 自动进入下一杆；若黑球仍在运动，则等待全桌停止后再进入下一杆。
5. 预测使用真实世界副本并共用 `Resolve(Goal)`，因此预测终点也会停在图形目标圆，保持预测与真实结果一致；同步修正与“预测穿过图形”冲突的注释。
6. 非白球即使配置为允许触发图形，也保留现有运动行为。本次需求明确针对白球，不扩大为所有球命中图形后强制停球。

不新增管理器、组件、事件、配置字段或 UI；不修改 `GoalJudge` 的数学判定与 `Session` 的回合状态机，符合单一职责、开闭原则及最小修改范围。

## 5. 事件顺序与边界

- 同刻事件继续沿用现有优先级：`Goal` 先于道具、球洞、球碰撞、库边和几何门。白球一旦成功，后续同刻的碰撞不会再让它离开目标位置。
- 使用理论 `Center`／`Radius` 吸附，而不是保留容差窗口中的最早边界值，确保画面上确实停在标准内切／外接位置。
- 白球停下后，半径不会继续变化；下一次成功出杆仍由现有 `Shoot()` 恢复增长趋势和本杆成长速率。
- 图形绑定的解锁或道具效果仍先正常提交，不能因为停球而遗漏效果。
- 若一个位置存在多个重叠图形，现有同刻稳定优先级仍只先处理一个事件；本次不扩展重叠图形的批量触发规则。
- 白球落袋、黑球入洞、犯规复位、暂停、重开与关卡胜负条件不在本次修改范围内。

## 6. 玩法影响与风险

当前部分关卡及参考解可能依赖“白球同一杆完成图形后继续前进，再推动黑球入洞”。改为图形成功即停白球后，这类路线会被截断，可能需要下一杆继续，进而影响最大杆数、候选参考解或关卡可解性。

本次建议只修改通用规则，不擅自同步调整关卡数据。代码完成后如用户要求检查，再单独验证受影响关卡，并依据真实回放结果决定是否调整杆数或布局。

另一个边界是目标位置被其他球占据。正常连续碰撞通常会先处理球碰撞，使白球无法直接到达有效目标状态；若后续配置制造同刻重叠，需要以实际复现结果决定是否增加目标位置占用保护，本次不预先添加重复判断。
