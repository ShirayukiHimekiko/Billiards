# 小球恢复 v0.2 连续缩放方案

日期：2026-10-11 · 任务等级：L3 · 状态：已按确认方案实施，未进行运行验证

## 现状与依据

- v0.2 的 `BallBase.ApplyState` 直接用模拟半径计算球面直径，以 `diameter / sprite.bounds.size.x` 缩放同一张球图；阴影和碰撞半径同步使用模拟半径。历史实现可在 Git 提交 `0f3f27f` 中查看。
- 当前 `BallBase` 将连续半径量化为 24 档，在每次更新时切换 `_displaySprites[displayIndex]`；球面、阴影和状态覆盖层使用离散显示半径。物理碰撞仍使用连续模拟半径。因此，球体视觉增长呈台阶状，物理增长本身未退化为离散值。
- 白球和黑球 Prefab 的 `Surface` 当前都已绑定原有 `ball_normal.png`。4 张白球状态覆盖图用于表达正常、逆转、冻结、疾变状态，与球体尺寸档位分开。
- GitHub 参考：[DarkRift Unity 示例](https://github.com/DarkRiftNetworking/DarkRift.Documentation/blob/master/getting_started/2_the_unity_scene.md)中的 `SetRadius` 通过固定 Sprite 的 Transform 缩放显示半径。其整体网络同步方案不适合本项目；这里只参考单图按半径缩放的做法。当前项目自身的 v0.2 实现更直接，优先恢复该实现。

## 修改方案

1. `BallBase` 不再按半径计算显示档位，也不再在 `ApplyState` 中替换球面 Sprite。初始化时确认 `Surface` 已绑定球图，继续使用 Prefab 上的 `ball_normal.png`。
2. 按 v0.2 方式，用连续模拟半径更新 `Surface.localScale`；阴影尺寸、偏移以及白球状态覆盖层尺寸也改为随连续半径变化。保留现有 `DisplayScaleMultiplier` 接口，若有子类倍率则仅作用于外观，不改变碰撞半径。
3. `CircleCollider2D.radius` 继续取模拟半径，保留现有增长、缩小、冻结、疾变、出杆和滚动相位规则。状态覆盖层仍可按状态切换图标；本次不改状态语义。
4. 通过项目规定的 Unity CLI 操作清理白球、黑球 Prefab 中不再使用的 24 档 `_displaySprites` 序列化数组，保留原有 Sprite、`.meta` 和 GUID。当前未提交的球桌与 UI 改动不纳入本次修改。

## 范围与边界

- 不替换球面图片，不删除已导入的 16BIT 图片资源，不改变物理半径或几何判定。
- 球体外观会再次对固定图片做连续缩放，像素边缘风格可能随尺寸变化；这是恢复线性变大的视觉代价。
- 按项目规则，未收到验证要求前不运行编译、测试、Unity 场景或其他验证。

## 实施记录

- `BallBase` 已恢复固定球图随连续模拟半径缩放，阴影和状态覆盖层同步使用连续显示半径；碰撞半径保持原值。
- 通过目标项目的 Unity Pipeline 重存白球、黑球 Prefab，清除了两份不再使用的 `_displaySprites` 序列化数组；原有 `Surface` Sprite 和状态覆盖层引用未改变。
- 未主动运行编译、测试或场景验证。Unity Editor 在处理脚本改动时自行更新了当前代码域，本记录不将其视为功能验收。
