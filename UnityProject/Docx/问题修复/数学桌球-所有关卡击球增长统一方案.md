# 数学桌球：所有关卡击球增长统一方案

## 需求解释

按现有球种职责，将本次“球”理解为玩家击打的白球。所有关卡均采用同一套白球尺寸规则：有效出杆时按力度设置起始半径并恢复增长趋势，滚动期间按模拟时间持续增长。图形只参与解谜和触发效果，不决定白球是否增长。黑球沿用固定尺寸。

保留半径上下限、贴边和贴球时的增长约束、暂停及停球时冻结尺寸、当前杆翻转道具切换增长/缩小的规则。每杆恢复增长意味着上一杆的缩小趋势不再延续到新杆。

## 当前代码与数据事实

- `Core/Physics/PhysicsWorld.cs` 的 `RadiusRate` 没有按图形有无启用增长的判断；白球按配置速率变化。
- `Configs/GameConfig/Datas/Ball.xlsx` 中白球 ID 1 的击球半径为 0.25～1，增长/缩小速率为每秒 0.12；白球 ID 3 的击球半径固定为 0.28，增长/缩小速率为每秒 0.00001。
- `Tools/ConfigureGameConfig.py` 同样生成上述两套白球参数，单独改运行时代码不能解决数据源差异。
- `Tools/Campaign.py` 的默认布局使用白球 ID 3，覆盖前五关及第九关。因此问题也出现在有图形的第九关，并非所有有图形关卡都会明显增长。
- `PhysicsWorld.Shoot` 设置半径和速度，没有重置 `Growing`；第十关的作者数据还依赖跨杆保留缩小趋势。
- `UI/MainUI.cs` 仅在 `_hasGeometry` 为真时显示大小趋势，将图形提示与通用尺寸反馈混在一起。

## GitHub 方案评估

已查询 Unity 桌球相关实现及 [DOTween](https://github.com/Demigiant/dotween)。DOTween 是 Unity 动画补间引擎，可用于表现动画；本项目的尺寸会参与连续碰撞、图形条件及预测，适合复用已有真实半径模拟和 `BallBase.ApplyState` 的显示/碰撞半径同步。此次不新增补间依赖或另一套半径计算。

## 拟修改内容

1. 将白球 ID 3 的击球半径范围、增长和缩小速率统一为 ID 1 的参数，保留已有配置 ID 和关卡引用，避免引用迁移。同步维护 `Tools/ConfigureGameConfig.py` 与 `Ball.xlsx`。
2. 在 `PhysicsWorld.Shoot` 接受有效出杆后设置 `white.Growing = true`。同杆翻转仍通过现有道具策略生效，失败的出杆不改变趋势。
3. 在 `MainUI.OnStateChanged` 中始终显示大小趋势；`_hasGeometry` 仅控制图形提示按钮，更新对应 XML 注释。
4. 更新 `Campaign.py` 中依赖固定半径、极低增长速率或跨杆缩小趋势的候选路线与图形尺寸推导，重点处理第五、九、十关。对应作者数据及候选解文档保持一致；候选解仍标记为未验证。第十关后续杆需要按重新增长的规则重新设计目标尺寸及路线，避免旧目标依赖失效。
5. 按仓库 Luban 生成流程同步运行时二进制配置，不手改生成 C# 类型或二进制内容。源表位于仓库级 `Configs/GameConfig`，是此次 Unity 配置修改所必需的关联范围。
