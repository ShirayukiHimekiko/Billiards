## 1. 最新需求与设计边界

用户要求：翻转道具放大；新增 PropManager 和 PropBase，翻转道具继承基类；两种切法互斥；不满足当前切法时碰目标圆反弹，满足时不反弹；桌面四边反弹；击球预测线随桌边反射，长度由力度决定，采用虚线和头部圆点。

术语沿用项目现有几何定义：**内切圆**位于三角形内并贴合三条边；**外接圆**经过三个顶点。用户口述的“外切／内接”暂按这两种既有目标理解，若指其他几何规则，需要先修订本节。

本版取代旧方案中的以下规则：

| 项目 | 原规则 | 本版规则 |
|---|---|---|
| 道具归属 | Session 保存 ItemUsed，BoardView 显示，GoalJudge 查询接触 | PropManager 管理道具；PropBase 定义公共约定；FlipProp 负责翻转效果 |
| 切法 | 单个三角形同时显示、查询两种 | 一关可有多个图形，每个图形各自只启用、显示、判定一种切法 |
| 目标圆 | 可隐藏的辅助线，不阻挡 | 各未完成图形的目标圆有条件阻挡；能够达成该图形切法则放行，否则反弹 |
| 四边 | 接触边界结束本杆 | 接触库边反弹，继续消耗本杆剩余路程 |
| 运动 | 力度改变速度，所有力度计划路程相同 | 力度同时决定速度、出球大小与计划路程 |
| 预测 | 固定长度直线，到桌边截断 | 共用运动规则的多段虚线，包含反弹与道具效果，末端显示圆点 |

继续保留单关演示、单白球、大小变化、道具每杆一次、瞄准后蓄力锁定方向、暂停和重开。一关内允许多个目标图形；不同图形可以分别采用内切或外接。杆数仍来自关卡配置，不将原三杆硬套到任意数量的目标。继承结构支持增加其他道具，但本次只实现翻转道具。

## 2. 需要随方案确认的建议

以下是设计建议，不冒充用户已指定的数值或细节：

1. **已确认：每个图形各自固定一种切法，一关可以有多个图形。** 不增加整关唯一切法或玩家切换按钮。多个图形的目标圆可以同时存在；同一个图形的内切与外接圆不能同时存在。
2. 翻转道具直径先放大为原来的 **1.3 倍**，触发半径同步乘 1.3，保持看见的尺寸与接触范围一致。倍率最终按试玩调节。
3. “头部原点”理解为**预测路线最远端的实心圆点**，表示预计停止或成功的位置。
4. 四边与目标圆先采用弹性反射，反弹瞬间不额外损失速度；原有滚动减速持续生效，不重置时间、尺寸变化或计划路程。
5. 目标圆采用下述“本次接近能否达成”的条件放行规则，避免实体障碍挡住所有通关路线。
6. **已确认：必须完成全部图形才能通关；每次成功停球，已完成目标保留进度。** 之后的击球继续处理剩余图形。

## 5. PropManager、PropBase 与 FlipProp

建议目录以既有 GameLogic 为根：

```text
Module/PropModule/PropManager.cs
Core/Prop/PropBase.cs
Core/Prop/FlipProp.cs
Core/Prop/PropData.cs
Core/Prop/PropEffect.cs
```

`Core/Prop` 替代旧文档尚未落地的 `Core/Item` 分类。本次确有道具基类和具体类型需求，才建立这些文件。

| 类型 | 职责与边界 |
|---|---|
| PropManager | 由 GameManager 持有，绑定道具实例和配置，提供只读接触数据，管理每杆使用状态、复位和释放；不决定本局输赢 |
| PropBase | 世界对象的 MonoBehaviour 抽象基类，统一初始化、位置与尺寸、效果描述、状态显示、复位与解绑；缓存 SpriteRenderer，不自行推进模拟或扣杆 |
| FlipProp : PropBase | 返回“翻转大小变化趋势”的效果描述；实际提交后更新已用外观，保持当前半径、位置、速度与剩余路程连续 |
| PropData | 道具 ID、类型、局部位置、触发半径等经校验只读数据 |
| PropEffect | 不含 Unity 场景修改的效果描述，供真实计算与预测计算共同应用 |

接触计算由规则层处理，输入为 PropManager 提供的只读数据和本杆使用状态。基类返回效果时不立即修改真实道具；共用模拟在自己的状态中标记已使用并应用效果，真实 Session 提交结果后才让管理器更新道具外观。预测仅复制本杆状态，不使道具变灰、不改变真实球、不扣次数、不发 UI 事件。

初版只需注册台面 Prefab 中的 FlipProp；不强制将一个道具拆成多个异步加载对象。未来独立加载道具时使用 `GameModule.Resource.LoadGameObjectAsync`，由明确的持有者回收。

当前 `ItemUsed` 的真值迁到道具运行状态，Session 的 UI 快照从管理器读取翻转道具状态，不再维护第二份可独立修改的布尔值。

进入顺序：读取关卡 → 准备台面 → 初始化球与道具 → 创建 Session → 绑定驱动与输入。释放顺序：解绑驱动和预测 → 释放 Session → 解绑 PropManager 和 BallManager → 卸载关卡、销毁台面。台面子对象只由台面根回收，避免重复销毁；需支持退出时 Unity 对象已被销毁。

## 6. 互斥目标与条件反弹

关卡提供目标集合，每个 `BilliardsTargetData` 包含 TargetId、图形几何、唯一 GoalKind、圆心、圆半径及判定容差。GoalKind 仅允许 Inscribed 或 Circumscribed；没有 Both 状态，也不用两个独立布尔值表达互斥关系。旧关卡的单个三角形迁移为集合中的一项。

LevelManager 根据每个图形的顶点计算它所选切法对应的圆心与半径，形成只读数据，供显示、成功判定与反弹使用，移除 BoardView 中独立重算圆心的逻辑。首轮建议支持多个现有三角形；用户尚未指定正方形等其他图形，不能直接承诺已有数学公式可覆盖任意多边形。

每个图形只显示并启用自己的目标圆，该图形另一种圆不参与显示、成功查询或阻挡。成功仍要求白球整体符合该图形的内切／外接条件，仅碰到目标圆或三角形一条边不算成功。GoalJudge 逐项查询未完成图形，返回最早成功时间、TargetId 和 GoalKind，不能只返回切法而丢失所属图形。同刻多个目标确实满足条件时提交候选集合，一次停球、一次发布进度，避免结果依赖目标遍历顺序。

**必须避免的逻辑矛盾：**若将目标圆无条件视为实心圆，外侧白球会在 `球心距离 = 目标半径 + 白球半径` 时先被挡住，而成功需要进入圆心附近。因此，仅在第一次碰撞瞬间检查成功再反弹，会让原本可解的路线被拦截。

建议规则为“本次目标接近是否能达成”：

1. 球与某个未完成图形的目标圆首次接触时，先以当前状态做只读前向查询。本次接近从首次接触开始，到白球与这个目标圆完全分离、自然停下、成功或接触另一个目标圆为止。
2. 前向查询暂时忽略**这一个目标圆**的阻挡，保留滚动减速、半径变化、尚未使用的翻转道具和桌边反射，查本次接近内是否存在该图形的有效成功时刻。碰到另一个目标圆时终止局部放行探测，避免多目标相互递归；只有该图形在此前可成功才放行。
3. 找到成功时刻则放行这次接近，真实球继续前进，到实际成功时刻停球并记录这个图形已完成，只有全部完成才结算整关。
4. 找不到则在首次接触处按圆法线反弹。离开后再次接近需要重新判定，不永久关闭目标障碍。
5. 局部前向查询不再次调用目标放行查询，避免递归。记录 TargetId 和本次接近标记，在成功或完全分离时结束；后续每次接近的判断都从当时真实状态开始。首轮关卡建议避免多个目标圆交叠，交叠布局需先明确同刻接触和局部放行语义。

因此，“这一杆之后可能成功”不能直接导致当前接近放行；必须是当前接近区间内可达成。与成功无关的方向即使半径合适也会反弹。

初版假定出生球在所有启用目标圆外，并在初始化时检查。未来若允许目标内部出生，需要另行定义圆周内侧阻挡规则，本轮不通过默认行为暗中扩展。

所有未完成图形的目标圆承担阻挡提示，保持可见。原提示按钮可隐藏额外几何辅助线，不能让启用中的障碍变成看不见的碰撞体。

### 多目标完成状态（已确认）

完成进度属于 Session 的本局运行状态，以 TargetId 标记，不写回关卡只读数据。每次成功停球、将对应图形标为已完成；全部完成才 Won。建议已完成图形取消后续成功查询与阻挡，显示保留为完成标记。尚有目标且还有杆数时，保留停球状态和完成提示，提供“下一杆”入口，玩家操作后恢复白球出生状态与道具，再进入 Ready；用尽杆数仍未全部完成则 Lost。普通失败只消耗杆数，不清除已完成目标；重新开始清空全部进度。完成后的阻挡关闭与下一杆出生点复位是实施建议，随本版方案一起确认。

按每次成功停球的规则，N 个独立目标通常至少需要 N 杆；旧版固定三杆在目标超过三个时可能无解，因此 MaxShots 必须随目标数量与难度配置。球停在成功位置时不继续改变大小或自动开始下一杆。

| 情况 | 本杆处理 | 进度和关卡结果 |
|---|---|---|
| 完成一个或同刻多个图形，仍有目标 | 成功时立即停球 | 保存进度；有杆数则等待下一杆，无杆数则 Lost |
| 最后一个目标完成 | 成功时立即停球 | 全部完成，Won；最后一杆完成也能通关 |
| 自然停止但未完成新图形 | 本杆失败 | 已完成进度保留；有杆数则重试，无杆数则 Lost |
| 重新开始 | 重置球、道具、机会与预测 | 清空本局全部目标进度 |

多目标显示建议增加 `Core/Level/BilliardsTargetView.cs`，每个实例绑定一个 TargetId、图形轮廓和一种目标圆。BoardView 只组织视图集合和预测绘制，关卡数据决定实例数量；复用已有几何绘制组件。目标实例若单独异步加载，由一个明确的视图持有者销毁；若作为台面子对象则跟随台面释放，不能同时由两方销毁。

## 7. 四边反弹与连续事件处理

新增规则对象 `BilliardsContactQuery`，负责桌边、目标圆和道具的最早接触，复用 PolynomialRoots；GoalJudge 保留静态与连续成功查询。Session 只协调输入许可、状态提交、机会和结果，不增加圆碰撞公式。

桌边接触计算考虑当前球半径及其变化，不能让球心撞到木框后才反弹。目标圆接触同样使用 `目标半径 + 当前球半径`，用最早有效根处理高速途中接触，不依赖触发器回调逐帧检测。

静止边界的反射公式为 `v' = v - 2 × dot(v, n) × n`。圆障碍法线沿目标圆心至白球球心；桌边使用面向台面的法线；桌角同时接触两边时翻转两个速度分量。减速方向随反射后的速度更新，速度大小不重置。

每个模拟区间先选最早时刻，推进到该时刻，再处理同刻事件：

1. 某图形的指定切法已成功：提交 TargetId 和完成状态，立即停球，抑制同刻目标圆与库边反弹；仅全部目标完成才结算整关成功。
2. 道具接触：按稳定道具 ID 应用尚未消费的效果，重新评估当前时刻成功及剩余轨迹。
3. 未满足放行条件的目标圆和桌边接触：按确定顺序解算反弹，同时处理桌角约束。
4. 自然停止：补查所有未完成图形；未成功则本杆失败，按剩余机会复位并保留本局已有完成进度。

事件重查不能重复扣杆、重复触发道具或重复结算。相比旧规则，普通桌边接触不再是失败条件；初始化非法位置和非有限配置仍属于准备错误。

白球持续变大可能在几乎不移动时接触边界，仅反转速度不足以保证不穿出。建议在接触约束持续存在时限制向外的半径增量，并将其作为共用模拟的分段约束；离开接触后恢复既有增长趋势，翻转道具仍可立即转为缩小。真实与预测采用完全相同的约束。最大球半径还必须能放入桌面，目标圆和道具布局不能制造无法分离的重叠障碍。

只对正在接近的接触面产生冲量，已经分离的球不再次反弹。使用可配置接触容差、接触状态和确定的分离处理，防止 t=0 重根造成无限反弹；计算安全上限不应像现有固定 8 次循环那样直接等同于合法反弹次数上限。极端配置造成无法推进时应给出明确的计算失败结果，不能宣称一个被截断的预测圆点是完整终点。

## 8. 力度、路程与共用模拟

建议增加最低和最高力度对应路程 Dmin、Dmax，默认采用线性映射：

`D(p) = Lerp(Dmin, Dmax, Clamp01(p))`

初速度继续沿用速度范围映射，出球半径继续沿用大小范围映射；本杆减速度变为 `a = v0² / (2 × D(p))`，自然停止时间为 `v0 / a`。无提前成功时，累计折线路程为 D(p)；每次反弹消耗已经走过的距离，不将下一段恢复成整杆长度。

具体路程端点留给调参。建议以现有 PlannedDistance 作为 Dmax 迁移参考，再配置 Dmin；本轮不擅自填写关卡数值，也不把“放大一点”转换成已确认数值。

新增普通 C# 的 `BilliardsSimulation` 与 `BilliardsSimulationState`：保存位置、速度、减速度、半径、增长趋势、剩余时间、道具使用状态、目标完成集合及当前目标接近状态，返回运动分段和带 TargetId 的事件结果。它没有 Transform、UI 或 GameEvent 依赖。

BallSimulationComponent 保留球能力入口并调用共用计算、将状态交给 BallBase 显示；Session 用同一计算处理实际推进；BallShootComponent 以当前方向、力度和配置生成状态副本，调用同一计算取得预测路线。对现有 Begin、PrepareSegment、Advance、Flip 的数学实现做必要迁移，不能在预测器里重新写一套简化运动。

目标放行查询也使用这个计算核心，明确关闭正在查询的那个目标阻挡且禁用再次放行探测，在其他目标首次接触处截断，复用道具效果、减速与桌边规则。

## 9. 虚线与末端圆点

BoardView 只接收已经算好的路径点并绘制，移除 SetAim 中固定距离和首次桌边截断的逻辑。球杆仍随蓄力后拉。

- 虚线从预计出杆球体前缘开始，沿球心运动路径经过各段反射；计算使用出杆半径，不能只取未蓄力时的出生半径。
- 路线包含桌边与目标圆的反弹，以及翻转道具引起的半径变化对后续接触的影响。
- 圆点标在完整预测的自然停止位置；途中完成某图形则标在该成功位置，并截断后面的路线，不将它误称为整关通关位置。下一杆预测从复位后的球状态重新生成，并忽略按方案已退出阻挡的完成目标。
- 使用世界空间 LineRenderer 与支持重复虚线的材质，按累计路径距离控制虚线相位；弯折处接续，蓄力变长时不将虚线整体拉伸成不同密度。
- 圆点使用世界空间 SpriteRenderer，与台面同一坐标系，屏幕观感保持清晰；不表示数学坐标原点，不用箭头替代。
- 未蓄力显示最低力度路线；蓄力时方向锁定，长度和终点随力度更新。取消恢复最低力度，出杆、暂停、失败结算和返回菜单时隐藏预测。
- 将路径缓冲区复用，记录方向、力度、关卡和道具状态版本，输入未变时使用缓存；局部前向查询使用独立计算上下文，不能污染真实模拟或另一次预测。

较大力度的计划总路程更长，但绕圈或反射后终点到出生点的直线距离不一定更远；途中成功也会提前截断。这属于折线预测的正常表现，力度条不应按端点直线距离计算。

## 10. 配置、资源与框架边界

| 数据／资源 | 拟调整内容 |
|---|---|
| 关卡配置源表 | 目标 ID 列表或关联目标表；各图形类型、顶点、唯一 GoalKind 与容差；道具描述及 MaxShots |
| 球参数源表 | Dmin、Dmax；必要的接触容差和计算安全预算配置 |
| LevelManager / BilliardsLevelData / BilliardsTargetData | 目标集合，各图形只有一种有效切法；统一提供目标几何与道具数据 |
| BilliardsTable.prefab / 目标显示实例 | 道具绑定 FlipProp；支持按目标集合绑定多个图形，每个只显示一种圆；预测虚线材质与末端圆点引用 |
| Session / SessionState / BilliardsUISnapshot / MainUI | 已完成目标集合、完成数／总数、各图形切法提示；新增目标完成后的等待下一杆状态及按钮；道具状态来源改为管理器快照；辅助提示按钮语义调整 |

继续沿用 Luban 和现有 ConfigSystem，不手改 GameProto 生成类或 bytes。配置数据源目前位于仓库根目录 `Configs/GameConfig`，后续实施需要对这部分关联源表作最小范围修改；本轮没有修改 UnityProject 以外文件。

按 `luban-dev` 读取源表结构，再修改并走项目现有生成流程。未经用户要求不执行导表中的额外验证、编译或运行检查；导表仅在代码实施和字段定义获确认后安排。生成字段与业务读取必须配套，不能声称仅新增业务类就已完成配置接入。

业务类型继续位于 GameLogic 热更程序集。PropManager 沿用现有普通业务管理器模式，不注册成新的 TEngine 框架模块、不再建立全局单例。资源异步加载与回收沿用项目 API，UI 通知使用 GameEvent，窗口监听使用 AddUIEvent。方法和属性按需提供 XML 文档注释，局部接触逻辑使用上方单行注释，不添加无意义的 try-catch 或重复前置判断。

## 11. 设计原则与实施顺序

PropBase 与 FlipProp 使用简洁继承约定，PropManager 依赖基类而非具体道具；具体效果保持可扩展。运动、成功判定、接触计算、生命周期和显示分别承担职责，预测与真实计算复用同一状态推进，符合单一职责、依赖倒置和合成复用的需要。基类只暴露必需接口，子类遵守相同初始化和复位语义，不按七大原则机械增加空接口、工厂或策略类。

确认后建议按依赖顺序完成：

1. 迁移单目标配置为目标集合，每个图形只启用其指定切法；接入全部完成通关、每次成功停球、进度保留与杆数规则；建立 PropManager → PropBase → FlipProp，道具尺寸与接触范围统一。
2. 抽取可复制状态的共用模拟，接入力度路程映射，保留大小变化和道具趋势翻转。
3. 接入桌边、桌角反弹与持续变大约束，替换原边界 Fail。
4. 接入各未完成目标圆接触、本次接近放行和带 TargetId 的成功提交；完成一个停球，全部完成才通关。
5. 用同一核心生成完整预测，绘制虚线与末端圆点，联动 HUD 和生命周期。
6. 更新涉及旧规则的实施说明。功能完成后询问用户是否需要检查，只有得到明确验证要求后才执行检查。

## 12. 后续可选检查范围（本轮未执行）

用户要求验证后，重点检查：

- 道具放大后可见范围与触发范围一致，每杆只翻转一次，重开复位，预测不会提前消费道具。
- 同关多个图形可采用不同切法，每个只启用自己的指定切法，错误切法不成功，不存在同图形隐藏的另一种目标碰撞。
- 目标 ID 与完成进度一致，完成后立即停球，同刻成功不重复提交；失败和下一杆保留进度，重开清空进度，最后一杆完成全部仍通关，杆数与目标数量不制造配置上的必然无解。
- 能成功的目标接近允许进入并停在成功时刻；方向或大小不合适的接近反弹；仅半径匹配不能放行。
- 四边、桌角、高速接触与多个事件在同一模拟步内处理正确；增长贴边不穿透、不反复产生零时长事件。
- 不同力度累计路程不同，反弹不重置路程；预测停止／成功的位置与真实计算结果一致。
- 翻转后再反弹、反弹后再接近目标均能正确重算；目标放行查询没有递归和真实状态副作用。
- 取消、暂停、重试、三杆耗尽、返回菜单和对象先销毁时，预测与管理器引用正确收尾。

添加了条件目标障碍和力度路程后，旧版已调好的直线通关力度可能失效，需要重新调关卡位置与球参数。新增前向查询也有计算成本，应在用户授权检查后评估极端反射路线与长时间性能。本方案未承诺未经实际运行得到的帧率或通关数值。
