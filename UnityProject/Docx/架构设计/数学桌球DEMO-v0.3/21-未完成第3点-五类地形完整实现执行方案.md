# 未完成第 3 点：五类地形完整实现执行方案

## 1. 当前事实

- 当前配置没有地形类型、地形摆放、出口引用和持续状态字段。
- `PhysicsWorld` 没有统一地形接触事件，也没有跳台、隧道、地陷、反向带、传送口状态。
- `Session.Restart()` 目前无法恢复地形局部状态。
- 当前工程没有对应的地形 Prefab 和表现资源。

## 2. 执行步骤

### 步骤 3.1：确定地形数据结构

1. 在 Luban 中增加 `TerrainKind`：`JumpPad`、`Tunnel`、`Pit`、`ReverseBelt`、`Teleporter`。
2. 增加位置、尺寸、方向、触发半径、持续时间、出口 ID、速度继承和旋转继承等字段。
3. 增加地形摆放表和可选地形样式表，资源地址只来自配置。
4. 在关卡入口校验每关最多 2 种地形、数值范围有效、传送口成对且出口存在。

### 步骤 3.2：建立地形运行时模型

1. 新增不可变的 `TerrainPlacementData`，将配置转换为已校验快照。
2. 新增地形运行状态，至少包含当前激活、冷却、入口锁定、腾空和陷入状态。
3. `LevelData` 统一保存地形列表，禁止在 `PhysicsWorld` 中直接读取 Luban 行数据。
4. `TerrainManager` 负责资源加载、实例化、同步和释放，遵循现有资源生命周期。

### 步骤 3.3：接入统一接触事件

1. 在固定步事件中增加地形接触事件，并明确与球体、洞、道具、三角形和库边的优先级。
2. 事件只报告接触事实，效果由地形策略处理，不在球体代码中堆叠五类分支。
3. 同一固定步设置触发标记，防止隧道和传送口在入口/出口之间重复触发。
4. 预测世界复用同一地形策略和状态复制规则。

### 步骤 3.4：实现五种地形策略

1. 跳台：进入后设置腾空状态、速度/方向和落地时刻；腾空期间跳过地面三角形接触。
2. 隧道：保存入口方向和出口状态，按持续时间或出口触发解除卡住状态。
3. 地陷：设置陷入状态，按配置恢复条件或重置恢复，不能直接结束关卡。
4. 反向带：在有效接触期间反转或重映射速度方向，效果结束后恢复正常运动。
5. 传送口：按成对出口转移位置，按配置继承速度、方向和旋转，传送后进入冷却。

### 步骤 3.5：接入生命周期

1. `Session.Restart()` 重建所有地形状态和球体地形状态。
2. 失败、通关、切关和离开关卡时取消地形延迟回调并释放实例。
3. 资源加载取消时回收已经返回的地形实例，不能留下半初始化对象。
4. 更新 HUD 可消费的地形状态，但地形不直接修改 UI。

### 步骤 3.6：制作资源并收口

1. 通过 Unity Pipeline 创建五类地形 Prefab 和所需材质/像素图标。
2. 将资源地址写入配置表并重新生成 Luban 代码和二进制。
3. 检查 Prefab 组件、碰撞范围、排序层和配置引用。
4. 更新执行日志，本点独立提交并推送 `main`。

## 3. 验收边界

- 五类地形均能从配置加载、产生统一接触事件、完成状态变化并可重置。
- 每关最多 2 种地形，传送口不能单独存在。
- 腾空、陷入、隧道和传送冷却状态不会绕过会话生命周期。
- 地形不直接结算胜负，通关仍由 `Session` 统一判断。

## 4. 依赖与风险

- 依赖第 1 点确定的几何接触时序和第 9 点重置入口。
- 需要策划先确认五类地形的持续时间、速度继承和恢复条件。
- 地形 Prefab、碰撞器和导入设置必须通过 Unity Pipeline 完成。
