## 2. 执行步骤

### 步骤 7.1：确认资源契约

1. 确认钥匙根节点使用 `KeyProp : PropBase`，接触半径和视觉直径继续读取配置。
2. 确认 SpriteRenderer、排序层、材质和 `PropBase._renderer` 序列化引用。
3. 确认钥匙拾取后由 `PropManager` 回收或隐藏，不能继续触发碰撞。
4. 确认钥匙图标、世界道具 Sprite 和 HUD 图标是否复用同一像素源。

### 步骤 7.2：通过 Unity Pipeline 生成资源

1. 在 `Assets/AssetArt/UIRaw/Raw/Props/` 生成 16×16 点采样钥匙图标。
2. 设置 Sprite 导入为 Point、Sprite、16 PPU、关闭 Mipmap。
3. 复制现有道具 Prefab 生成 `BilliardsKeyProp.prefab`，替换组件为 `KeyProp`。
4. 替换 SpriteRenderer 精灵并保存 Prefab 序列化引用。
5. 重新导入资源，检查 Sprite 子资源和 Prefab 无 Missing Script/引用。

### 步骤 7.3：补齐连接线和拾取反馈

1. 在关卡表现层读取钥匙的 `TargetPocketId`，建立钥匙到绑定洞的稳定映射。
2. 只为锁定洞绘制同色、低干扰的像素连接线；洞解锁后隐藏连接线。
3. 拾取成功时发布一次反馈事件，表现层播放短暂提示并回收钥匙实例。
4. 重置或重建关卡时恢复连接线、钥匙实例和洞锁定状态。

### 步骤 7.4：补齐 HUD 数据

1. 在会话快照中提供钥匙总数、已拾取数量和绑定洞状态。
2. HUD 只消费快照，不直接访问 `PhysicsWorld` 数组或 Prefab。
3. 绑定关系用图标/颜色/连线表达，不显示几何答案数值。

### 步骤 7.5：收口与提交

1. 检查 25 个钥匙配置的 Prefab 地址、TargetPocketId 和摆放位置。
2. 检查每个钥匙只绑定一个锁洞，钥匙只触发一次。
3. 更新执行日志，记录 Pipeline 目标实例、生成资源、静态引用检查和提交号。
4. 本点独立提交并推送 `main`；资源生成失败时保留明确阻塞记录，不提交伪造资源。
