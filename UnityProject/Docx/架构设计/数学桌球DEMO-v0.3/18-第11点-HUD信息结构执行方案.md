# 第 11 点：HUD 信息结构执行方案

## 1. 目标

补齐 v0.3 需要的 HUD 信息：杆数、黑 8 数量、洞态、钥匙绑定、半径趋势、冻结/疾变/预演等持续状态，并区分当前状态和下一杆预演。

## 2. 当前实现与差异

- 当前 `MainUI` 主要显示剩余机会、剩余黑球、大小趋势、道具触发、力量百分比和滑块。
- 当前没有持续效果图标、四类洞态硬提示、钥匙绑定、半径演化曲线和预演状态区分。
- 当前 `PredictionPropWidget` 的手动折射预测不能直接代表 v0.3 的预演道具。

## 3. 执行步骤

1. 先定义 HUD 数据契约：会话状态、白球状态、道具时效、洞状态、钥匙收集、黑 8 统计和反馈事件作为唯一来源。
2. 在 `MainUI` 生命周期中增加序列化绑定的状态槽位，不在 UI 中直接访问物理对象内部字段。
3. 增加半径趋势、正常/逆转/冻结/疾变状态和时效进度；一次性拾取反馈不得永久占用持续状态区域。
4. 增加下一杆预演区域，显示轨迹和半径演化曲线，并明确与当前球状态的视觉区分。
5. 增加洞四态、钥匙绑定和黑 8 进度提示，使用图标/图案表达，不用数字直接泄露几何答案。
6. 将重置、离开关卡、通关、失败和选关切换接入 HUD 清理/刷新事件。
7. 按移动端和 16BIT 约束确定布局优先级，避免洞态、杆数、力量条和反馈提示互相遮挡。

## 4. 影响范围

`MainUI`、预测道具 UI、洞/钥匙状态、白球状态、会话事件、Prefab 节点绑定和像素图标资源。

## 5. 依赖与待确认

- 依赖第 2、4、7、8、10 点提供稳定数据和表现资源。
- 需要确认预演曲线是否只在拾取预演道具后出现，以及 HUD 是否显示具体剩余时长。
- 需要确认洞态提示显示全部洞，还是只显示当前可交互洞。

## 6. 交付边界

本方案只负责信息汇总与表现绑定，不在 HUD 中直接驱动物理、道具或通关逻辑。
