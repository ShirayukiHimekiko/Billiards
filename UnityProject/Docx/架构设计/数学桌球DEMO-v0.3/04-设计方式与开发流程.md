# 数学桌球 DEMO v0.3：设计方式与开发流程

## 1. 设计支柱

| 支柱 | 设计问题 |
|---|---|
| A 几何洞察 | 玩家是否因为观察半径、位置和几何关系而做出选择 |
| C 可控的意外 | 场上元素是否会产生可预测的连锁影响 |

任何机制都要同时回答这两个问题。只增加操作复杂度、只制造随机结果或无法由玩家预判的效果，不纳入 v0.3。

## 2. 关卡制作顺序

1. 先确定黑 8、洞和三角形的几何关系，再计算内切/外接目标半径。
2. 设置白球出生点和杆数，确保至少存在一条可理解的解。
3. 每关先加入不超过两种地形，再加入不超过四种道具。
4. 用目标环和预亮反馈调节帮助强度，不用数字直接告诉玩家答案。
5. 最后布置钥匙、洞态和黑 8，让资源使用形成可控连锁。

## 3. 难度调节

| 体验问题 | 优先调整 |
|---|---|
| 到不了三角形 | 出生点、方向、杆数和地形位置 |
| 到达时半径不合适 | `rMin`、`rMax`、力量映射和变化速率 |
| 反馈不易理解 | 目标环目标选择、环带宽度和预亮次数 |
| 道具连锁太弱 | 道具位置、时效和与地形的接触顺序 |
| 局部死局太多 | 重置入口可见性、地陷位置和隧道口径 |
| 洞态难以辨认 | 固定像素标识的形状和轮廓，而不是继续增加文字 |

一次只调一类参数，并保留可复现的关卡数据。半径边界行为、纯半径判定和传送口规则在待定项确认前不得作为隐藏关卡技巧。

## 4. 视觉与交互约束

- 常态球使用琥珀色与外扩箭头，逆态球使用青蓝色与内收箭头，冻结球使用降饱和度和冰壳描边。
- 地形优先靠图案区分，不把颜色作为唯一识别渠道。
- HUD 固定为左上持续效果、右上杆数、底部力量条；力量条使用分段表现。
- 洞的四态使用固定像素标识，最小显示尺寸下仍需能区分。
- 目标环只表达几何差距，不叠加数字和文字面板。

## 5. 评审清单

- 是否同时服务 A 和 C。
- 是否遵守每关最多两种地形、四种道具。
- 是否存在只有杆数耗尽才失败的路径。
- 是否能通过重置全关脱离地陷和隧道卡住。
- 是否能从画面推断半径方向和洞态。
- 是否把待定项误写成固定规则。
