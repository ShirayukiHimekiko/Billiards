# 未完成第 2 点：8 项道具完整实现执行方案

## 1. 当前事实

- `PropKind`、`PropEffectKind` 和配置联合 Bean 已扩展到 v0.3 类型范围。
- 逆转、冻结、复原、疾变、钥匙已有基础策略；钥匙的洞解锁入口已完成。
- 显影、预演、加杆仍返回 `UnsupportedPropEffect`，运行时会抛出未支持异常。
- `durationShots` 已存在于配置，但运行时没有统一的持续效果状态和到期处理。
- 其他道具的正式配置、摆放、Prefab 和 HUD 表现尚未形成闭环。

## 2. 执行步骤

### 步骤 2.1：冻结道具数据契约

1. 确认每类道具的触发模式、作用范围、持续杆数、是否可叠加和重置行为。
2. 在 `PropEffect` 中统一表达 `durationShots`、`rateMultiplier`、目标引用和一次性资源变化。
3. 在配置入口校验参数：持续杆数不得为负，钥匙必须有绑定洞，预演必须有可用预测能力。
4. 保留未知类型的显式错误，不将未知类型降级为翻转。

### 步骤 2.2：建立会话级持续效果状态

1. 在 `Session` 或其专属状态对象中保存当前杆次、效果开始杆、剩余杆数和来源道具 ID。
2. `PhysicsWorld` 只读取已解析的状态快照，不在碰撞分支中维护倒计时。
3. 出杆、重置、失败、通关和离开关卡时统一推进或清理效果状态。
4. 预测世界复制持续效果状态，保证预测与真实世界使用同一组输入。

### 步骤 2.3：完成显影效果

1. 通过会话事件向几何显示服务发布显影状态。
2. 显影只控制目标可见性和显示时长，不改变 `GoalJudge` 的判定数据。
3. 新杆、重置和离开关卡时取消过期显影回调。
4. 无几何目标的关卡在准备阶段暴露配置错误或隐藏无效道具。

### 步骤 2.4：完成预演效果

1. 将预演定义为下一杆预测能力，而不是当前手动反射轨迹开关。
2. 复用 `PredictionPath` 和半径模型输出轨迹、接触点及半径变化曲线。
3. 预演只在道具已拾取且状态有效时显示，并按配置杆数自动结束。
4. 预测失败时显示明确状态，不得静默使用旧轨迹结果。

### 步骤 2.5：完成加杆效果

1. 由会话统一修改剩余杆数，不能让道具 Prefab 直接写 UI 文本。
2. 限制加杆次数和上限，参数由配置提供。
3. 将加杆状态纳入预测副本、重置和通关快照。
4. HUD 通过 `SessionUISnapshot` 消费变化。

### 步骤 2.6：补齐资源与关卡数据

1. 为显影、预演、加杆、逆转、冻结、复原、疾变、钥匙配置正式 Prefab 地址。
2. 为每个关卡生成摆放数据，校验每关最多 4 种道具。
3. 通过 Unity Pipeline 生成或修改 Prefab、图标和序列化绑定。
4. 资源导入完成后检查配置地址、Prefab 组件类型和回收路径。

### 步骤 2.7：统一收尾

1. 接入 `Session.Restart()`、失败、通关和离开关卡的效果清理。
2. 更新执行日志，记录配置生成、资源生成、静态检查、提交号和推送结果。
3. 本点独立提交并推送 `main`，不混入其他未完成点的业务修改。

## 3. 验收边界

- 八类道具均有可加载配置、可拾取入口、明确效果和可回收表现。
- 不再由 `UnsupportedPropEffect` 承担正式配置类型。
- 持续效果按配置杆数结束，重置后不残留。
- 每关道具种类不超过 4 种，钥匙绑定校验继续有效。

## 4. 依赖与风险

- 依赖第 4 点半径状态模型、第 7 点钥匙资源、第 10 点图标表现和第 11 点 HUD 数据契约。
- Unity 资源生成必须通过 Pipeline；若许可证或编辑器实例不可用，只能完成代码/配置部分并记录阻塞，不能手写 Prefab YAML。
