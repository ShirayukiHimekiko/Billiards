# 数学桌球 DEMO v0.3：分部功能执行方案

> v0.3 策划案状态为待评审。以下是评审通过后的推荐制作顺序，当前各阶段均不标记为已完成。

| 阶段 | 内容 | 交付标准 |
|---|---|---|
| M1 | 白球半径演化、力量映射、三角形内切/外接判定 | 能在接触瞬间稳定识别两类几何解 |
| M2 | 未命中目标环、失败计数和预亮梯度 | 失败反馈连续、无数字面板，不改变判定结果 |
| M3 | 8 项道具、四态洞、钥匙绑定、黑 8 入洞 | 拾取即生效，洞态与通关统计一致 |
| M4 | 5 类地形 | 每类接触效果明确，腾空和卡住状态可恢复 |
| M5 | 16BIT 表现和 HUD | 半径档位、洞态标识、持续效果和杆数清晰可读 |
| M6 | 关卡数据和手感调优 | 在约束上限内形成可解关卡，参数可从数据调整 |

## 1. M1：几何核心

- 固化 `r0 = Lerp(rMin, rMax, P)`、`k = Lerp(kMin, kMax, P)` 和 `v = Lerp(vMin, vMax, P)` 的数据契约。
- 预计算三角形内心、内切半径、外心和外接半径。
- 在边界接触瞬间比较当前半径与两个目标半径，使用统一 `eps`。
- 先完成纯数据判定，再接入运动和停球。

## 2. M2：反馈梯度

- 未命中时记录命中的三角形和失败次数。
- 选择内切/外接中更接近当前半径的目标，只显示一个同心环。
- 同一三角形失败 5 次首次预亮，之后每 2 次再次预亮；成功清零。
- 反馈必须随重置、离开关卡和成功结果一起失效。

## 3. M3～M4：交互内容

- 先接入演化、信息、资源三组道具，再接入地形公共接口。
- 每关数据校验道具不超过 4 种、地形不超过 2 种。
- 洞状态和钥匙绑定归 `HoleActor`，黑 8 全部入洞归 `LevelController` 统计。
- 地陷、隧道卡住等局部状态必须被重置全关覆盖。

## 4. M5～M6：表现与调优

- 使用 20～24 档半径精灵，避免运行时缩放造成锯齿。
- 四种洞态在最小显示尺寸下仍需可辨认。
- 关卡只通过数据调整位置、目标半径、奖励和障碍组合；不在关卡脚本中硬编码特殊分支。
- 评审通过前不把任何阶段写入“已实现”验收记录。

## 5. 阶段依赖

`M1 → M2 → M3 → M4 → M5 → M6`。M2 依赖稳定的命中结果，M3 依赖稳定的本局重置和结算，M4 依赖统一碰撞时序，M5 和 M6 依赖前面规则不再频繁变化。
