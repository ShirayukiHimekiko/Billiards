# 第 2 点：8 项道具执行方案

## 1. 目标

将当前仅有的 `Flip` 道具扩展为 v0.3 的 8 项道具：状态逆转、冻结、复原、疾变、显影、预演、加杆、钥匙。所有道具均通过拾取事件立即生效，每关最多出现 4 种道具。

## 2. 当前实现与差异

- 当前 `PropManager`、`IPropEffect`、`PropEffects` 已提供策略入口。
- 当前配置和运行时枚举只有 `Flip`。
- 当前预测 UI 是手动开关反射轨迹，不等于拾取即生效的“预演”。
- 当前没有冻结、复原、疾变、显影、加杆和钥匙的统一状态契约。

## 3. 执行步骤

1. 扩展 Luban 道具配置和 `GameConfig.PropKind`，固定 ID、名称、分类、持续时间、作用杆次和表现资源引用。
2. 扩展热更侧道具类型转换，未知 ID 必须在关卡准备阶段暴露错误，不在运行时静默当成 `Flip`。
3. 按策略职责拆分效果：半径演化类修改白球状态输入；信息类发布几何/预测显示状态；资源类修改杆数或钥匙库存；钥匙由洞状态管理器消费。
4. 统一拾取事件入口，确保物理碰撞、道具表现和效果应用只提交一次；拾取后隐藏或回收道具实体。
5. 给持续效果增加开始、刷新、结束和重置清理入口，避免 `Update` 中散落倒计时。
6. 将显影接入三角形目标显示，将预演接入下一杆轨迹与半径曲线，而不是继续复用旧预测开关。
7. 在关卡数据准备阶段校验每关道具种类不超过 4 种、参数完整、资源可加载、钥匙绑定有效。
8. 在 `Session.Restart()`、离开关卡和通关时统一清理道具状态、表现和延迟回调。

## 4. 影响范围

`PropManager`、`PropEffectKind`、`PropEffects`、`PropKindConverter`、道具配置、道具 Prefab、白球状态、几何提示、预测 UI、杆数和洞状态。

## 5. 依赖与待确认

- 依赖第 4 点的半径模型，先确定冻结、疾变、复原的作用时机。
- 依赖第 7 点的钥匙绑定方案。
- 需要确认每个道具是一次性、持续到本杆结束，还是持续若干杆。
- 需要确认显影和预演的获得方式、持续时间及是否可以叠加。

## 6. 交付边界

本方案只负责道具类型、配置、拾取和效果派发；不在道具 Prefab 中直接决定通关，不在 UI 中直接修改物理状态。
