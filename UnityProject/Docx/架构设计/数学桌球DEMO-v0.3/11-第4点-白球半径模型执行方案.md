# 第 4 点：白球半径模型执行方案

## 1. 目标

实现 v0.3 的本杆半径与速度模型：出杆时根据力量计算 `r0`、基础变化速率 `K` 和初速度 `V`，滚动中按趋势和实际速率推进半径，并支持正常、逆转、冻结、疾变、复原状态。

## 2. 当前实现与差异

- 当前半径会跨杆保留，出杆时强制进入增长状态。
- 当前主要按力量调整增长速度，没有统一的 `Normal / Reversed / Frozen` 状态。
- 当前没有冻结、疾变、复原对半径模型的明确输入契约。
- 上下限触及时的停住/反向规则仍待策划确认。

## 3. 执行步骤

1. 在物理或关卡配置中补齐 `rMin`、`rMax`、`kMin`、`kMax`、`vMin`、`vMax` 和容差参数，并在数据入口统一校验范围。
2. 在现有球状态层增加独立的半径计算职责，出杆时生成本杆快照：初始半径、方向、基础速率、初速度和有效效果。
3. 固定步中只由半径模型推进 `r(t)`，`PhysicsWorld` 负责提供实际速率和时间步，不在碰撞分支中直接改半径。
4. 将状态逆转映射为方向变化，冻结映射为有效变化速率 0，疾变映射为速率倍率，复原映射为恢复 `BaseR`。
5. 在边界策略确认后，把停住或反向实现集中在模型内部；其他模块只能读取裁剪后的结果。
6. 更新重置快照，使重置恢复初始半径、方向、效果时效、杆数和球运动状态。
7. 删除旧的跨杆保留和每杆强制增长语义，检查几何判定、预测轨迹和 HUD 是否改为读取统一模型。

## 4. 影响范围

白球运行状态、`PhysicsWorld` 固定步、力量输入、道具效果、几何判定、预测显示、16BIT 资源映射和 HUD。

## 5. 依赖与待确认

- 必须先确认半径触及 `rMin/rMax` 后停住还是反向。
- 需要确认复原是立即恢复当前半径，还是仅恢复本杆基准值。
- 第 1、2、5、10、11 点都会消费本方案提供的半径状态。

## 6. 交付边界

本方案只统一半径和速度输入，不负责几何成功、道具拾取或 UI 表现的最终结算。
