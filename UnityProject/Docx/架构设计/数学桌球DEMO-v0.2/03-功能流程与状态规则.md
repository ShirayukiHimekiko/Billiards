## 1. 一局游戏怎样进行

进入时由 GameManager 组织：LevelManager 准备并校验关卡数据与桌面/目标，BallManager 初始化白球，然后 Session 接收关卡快照和球管理器。全部必要内容准备成功后才允许击球。

应用启动先显示全屏 StartUI；点击开始调用 `GameManager.Instance.StartGameAsync()`，先关闭开始界面再打开全屏 MainUI，在加载反馈期间完成上述准备。设置打开非全屏 SettingsUI，开始界面仍可见且输入被遮罩阻挡；四类音量即时调整，关闭后恢复菜单操作。详见[设置设计](../../功能开发/数学桌球-设置界面与四类音量设计.md)。存档和制作详情保留占位。开始界面或游玩界面的退出请求都退出应用。

1. 进入关卡，摆好白球、三角形和道具，显示剩余3杆。
2. 移动鼠标瞄准。
3. 按住左键蓄力，锁定当前方向。
4. 松开左键出杆，消耗1杆，白球开始滚动。
5. 滚动期间检查道具、目标和桌面边界。
6. 完成内切或外接，立即停球并显示成功。
7. 越界或停下仍未达成目标，本杆失败。
8. 还有机会就恢复出生点继续；机会耗尽则显示关卡失败。
9. 重开后恢复3杆、初始白球和道具。

## 2. 道具流程

白球接触道具 → 保持当前大小 → 切换变大或变小的方向 → 更新球体外观和状态提示 → 继续滚动。

道具每杆只触发一次，下一杆恢复可用。触发时不改变速度、方向或计划路程。

## 3. 关键情况怎么处理

| 情况 | 处理 |
|---|---|
| 蓄力时取消 | 返回瞄准，不消耗杆数 |
| 球还在滚动时再次点击 | 不允许重复出杆 |
| 球经过目标时短暂贴合 | 当时就成功，不能等停下才检查 |
| 球因变大而越界 | 本杆失败，不能只看球心是否在桌内 |
| 球碰到桌面边缘 | 不反弹；跨出边界才失败 |
| 第三杆完成目标 | 正常通关，不因机会已扣完而失败 |
| 暂停或窗口失焦 | 停止游戏推进，恢复后接着原位置继续；蓄力失焦则取消蓄力 |
| 成功后点击重开 | 清除旧结果，恢复初始状态 |
| 退出游戏 | 使本局与加载请求失效，停止输入、模拟与反馈并清理内容，然后退出应用；Editor 中结束 Play Mode |

多个事情同时发生时，先处理出界，再处理成功，然后处理道具，最后处理正常停止。一次出杆只产生一个最终结果。

上述时间顺序由 Session 统一协调；目标结果由独立 GoalJudge 计算，球模拟按协调结果提交状态。LevelManager 只负责关卡数据和内容生命周期，不参与扣杆或胜负结算。

相近但不同的事件不能直接当作同刻，先细化到能够确定顺序。道具先发生时只改变半径趋势，丢弃原趋势下的后续候选并重查剩余区间；成功或出界终止该杆。暂停限制由 Session 持有，关闭窗口不能自行恢复模拟。
