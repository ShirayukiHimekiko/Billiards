## 已确定的方向

- 单关卡、单白球、俯视二维桌面。
- 每杆计划路程相同，力量越大，速度越快，完成路程所需时间越短。
- 力量也决定出球大小，滚动中球会持续变大或变小。
- 内切或外接任意一种达成即可通关。
- GameManager 负责入口与生命周期；LevelManager 管理关卡数据；BallManager 管理球；本局流程统一处理操作许可与结果。
- 球基类保留初始化、显示、位置与大小同步和复位；击球组件合并瞄准与蓄力出杆，模拟组件合并运动与大小变化。
- 内切、外接由独立目标判定器计算，不作为球的能力组件；显示与判定使用同一份关卡数据。
- 管理器分别放 Module/GameModule、Module/LevelModule、Module/BallModule；具体业务在 Core/Ball、Level、Rules、Session、Item、Events 下分类，球组件在 Core/Ball/Components，窗口沿用 UI 和实际生成器配置。
- UI 窗口类名按用途简写为 StartUI、MainUI、SettingsUI，省略项目名前缀；前两者全屏，设置为非全屏弹窗。主界面新资源地址暂定 GameMainUI，以区分现有示例 MainUI.prefab。
- 多关、黑8、钥匙和球袋放在后续版本。

## 当前配置方式

关卡与玩法参数使用 Luban Excel，当前源文件在仓库根目录 Configs/GameConfig/Datas/#billiards_level.xlsx 和 #billiards_ball.xlsx。业务按 luban-dev 经 ConfigSystem.Instance.Tables 查询，LevelManager 在 Module/LevelModule 构建 Core 中的经校验快照；球、Session、判定器和 UI 不自行读表。台面与窗口仍异步加载。当前生成的 Tables 为空，桌球表、向量类型和 bytes 待补齐，不能标记配置已接通。调参后需重新导出并重新启动应用读取，不在局中热换配置。具体状态见[Luban 设计](../数学桌球-Luban配置表与数据分层设计.md)及[技能对齐修复方案](../../问题修复/数学桌球-Luban技能对齐修复方案.md)。

## 本版采用的默认规则

每关3杆；起始为变大状态；道具每杆触发一次；不反弹；球体越界时本杆失败；显示可隐藏的目标虚线圆。这些规则沿用上版建议，具体大小、速度和贴合宽松程度留给试玩调整。

这些规则已用于单关初版。结果在主界面显示，通过重新开始继续试玩，未增加独立结果页面。

初版曾按用户“直接按照目前方案实施，做一版初版”指令实施并记录验收；该结果只适用于历史版本。本轮修改配置业务入口和文档，未执行导表、编译、测试或 Unity 验证。
