## 1. 结论

| # | 判断 | 说明 |
|---|------|------|
| 1 | 方向成立，但**不是新立约定** | 球与球桌已经是「根节点放脚本、子节点放 Renderer」。本提案的实质是**把道具与地形补齐到同一约定**，属于统一化，不是架构变更。 |
| 2 | 必须把**子节点命名**一起定为约定 | `BallBase` 已经按节点名取节点（`Surface` / `BallShadow`）。只拆层级不定名，就会退回手工拖序列化引用，收益减半。 |
| 3 | 不要把这条约定说成性能优化 | 拆层级会让实例多一层 Transform，渲染开销不变。收益是**一致性与可扩展性**（表现分层、描边/阴影/高亮独立挂载、排序独立控制）。 |
| 4 | 需要补一条硬约束 | 父节点是非均匀缩放且带旋转时，子节点**不得再引入旋转**，否则出现剪切（skew）。地形当前正好是这种父节点。 |

## 3. 约定正文

### 3.1 层级

```
<Prefab 名>            ← 行为脚本 + 碰撞体 + 逻辑 Transform（不挂任何 Renderer）
├─ Surface / Visual    ← 主体显示（SpriteRenderer）
├─ Shadow              ← 阴影（MeshRenderer / SpriteRenderer）
└─ Overlay             ← 状态叠加、高亮、遮罩（按需）
```

规则：

1. 根节点**只放行为脚本**（`BallBase` 子类、`PropObject`、`Terrain` 等）和碰撞体。
2. 所有 Renderer（Sprite / Mesh / Line / Trail）一律放在子节点。
3. 根节点承担模拟坐标与朝向；子节点承担显示尺寸、偏移、排序、颜色。

### 3.2 子节点命名

| 节点名 | 用途 | 约定类型 | 当前使用方 |
|--------|------|---------|-----------|
| `Surface` | 主体显示层（球） | SpriteRenderer | `WhiteBall` / `BlackBall` |
| `StateOverlay` | 状态叠加层（球的状态语义） | SpriteRenderer | `WhiteBall` |
| `BallShadow` | 阴影层（球） | MeshRenderer | `WhiteBall` / `BlackBall` |
| `Visual` | 主体显示层（道具、地形） | SpriteRenderer | 9 个道具 + 5 个地形 |

命名即契约：改名必须同步修改读取它的脚本常量（`BallBase.SURFACE_NODE_NAME` / `SHADOW_NODE_NAME`、`PropObject.VISUAL_NODE_NAME`、`Terrain.VISUAL_NODE_NAME`）。当前节点名以各类内的 `private const string` 保存，未抽公共常量表。

### 3.3 组件获取方式

**采用「约定节点名 + 初始化时自动获取」**（与 `BallBase` 一致），弃用序列化引用。

| 方式 | 做法 | 评价 |
|------|------|------|
| **约定节点名 + 自动获取（已采用）** | 沿用 `BallBase` 的 `GetRequiredChild(name)` + `GetRequiredComponent<T>()` 模式，在初始化边界一次性缓存并报错 | 与球体方案统一；新建预制体不会因忘记拖引用而静默失败 |
| ~~序列化引用~~ | ~~`[SerializeField] private SpriteRenderer _renderer` 手工拖~~ | 已移除：拆层级后必须重拖引用，漏拖会在运行时抛异常 |

已实施：`PropObject.cs` 与 `Terrain.cs` 均删除 `_renderer` 序列化字段，改为 `transform.Find("Visual")` + `GetComponent<SpriteRenderer>()`，缺失时抛带道具/地形 ID 与节点名的异常。错误信息按「缺子节点 / 缺渲染器 / 缺 Sprite」三档区分。

### 3.4 硬约束

1. **父级非均匀缩放下，子节点不得再引入旋转**。地形根节点当前同时承担 `localScale = data.Size` 和 `localRotation = FromToRotation(...)`（`Terrain.cs:22-23`），子节点如果再旋转会出现剪切变形。
   规避方式二选一：① 尺寸写到子节点，根节点只保留位置与朝向；② 保持现状并约定子节点不做旋转。
2. 渲染器不在根节点后，**禁止**在脚本中使用 `GetComponent<SpriteRenderer>()` 取主体显示层（会取到 null 或错误的组件）。
3. 子节点的 `SortingOrder` 由预制体固定，脚本只改颜色/缩放，不改排序，避免表现层互相覆盖。

## 4. 迁移成本与风险

| 风险 | 说明 | 处理方式 |
|------|------|---------|
| Prefab 覆盖丢失 | 移动组件/节点会改动 fileID，场景中已摆放实例上的 override 可能失效 | 迁移前确认场景覆盖项；Unity 资产修改走项目规定的 Unity CLI / AssetDatabase 路径，**不要文本直接改写 prefab**（依据：`Docx/架构设计/数学桌球-道具组件化与模拟解耦设计方案.md` 第 87 行） |
| 序列化引用失效 | `_renderer` 指向的组件被移动后引用需重拖，漏拖则运行时抛异常 | 改为按节点名自动获取（3.3 首选方式） |
| 实例多一层 Transform | 层级变换传播、遍历成本略增 | 数量级可忽略（道具个位数、地形几十个），接受 |
| 关联改动 | 拆层级与「修复道具预制体脚本失效」是同一批文件的同一轮改动 | 合并处理，避免二次触碰同一预制体 |
