# 数学桌球：五类地形系统架构优化方案

日期：2026-10-11 · 任务等级：L4 · 状态：详细实施方案待确认，未修改功能代码

## 1. 结论与边界

保留现有 `PhysicsWorld` 连续事件模拟及其预测副本机制；将「地形接触候选与效果执行」从世界主循环抽成纯 C# 的地形规则层，仍由同一个世界时间轴驱动。`TerrainManager` 继续管理 Prefab 生命周期和表现，`TerrainPlacementData` 继续由 `LevelModule` 输出。五种地形各有独立规则，只有真正共用的接触调度、状态复制、重置和表现同步保留在公共层。

本方案解决当前职责混杂和策划语义偏差，不更换 Unity 物理引擎，不增加 asmdef，不改 `UIModule`、`UI/Gen`、胜负结算或既有道具系统。地形不是可拾取道具；「地形触发」属于模拟内部事件，不通过全局 `GameEvent` 广播每次接触。面向 UI/音效的低频反馈可由会话层在模拟提交后发布。

## 2. 核对后的现状

| 位置 | 事实 | 对需求的影响 |
|---|---|---|
| `Core/Physics/PhysicsWorld.cs` | 找最早接触、处理五类效果、倒计时、地陷脱出和传送均在同一类；地形定时器在整步开始时减少 | 规则增长会继续扩大世界类；落地、出隧道等状态转换可能落在本步内，却只在步首处理 |
| `Core/Terrain/TerrainBallState.cs` | 多个布尔值共用一个 `Remaining`、`TerrainId` 和传送冷却 | 不同效果的互斥或叠加关系不清；同一球进入其他地形时容易覆盖前一状态 |
| `Core/Terrain/TerrainRuntimeState.cs` | `EntryLocked` 和 `CooldownRemaining` 属于地形实例，由所有球共享 | 一颗球触发后会短时阻止另一颗球进入，且无法准确表达「球 A 已离开，球 B 仍在内」 |
| `Core/Physics/PhysicsWorld.cs` | 跳台把速度乘倍率，按时间结束腾空；仅跳过三角形实体边界；反向带按 `Duration` 持有状态 | 没有显式的速度到飞行距离契约；「不与地面物碰撞」「经过时仅反向一次」没有完整落地 |
| `Core/Physics/PhysicsWorld.cs` | 隧道以地形中心圆触发，用尺寸较短边推算口径，按固定时间通过；传送到出口中心，出口方向可覆盖入射方向 | 隧道缺少真正的入口、通道和出口；传送保向不由策划规则强制，出口中心可能仍位于触发区 |
| `Module/LevelModule/LevelData.cs` | 校验最多两种地形、ID、台面范围及传送目标存在 | 已有入口校验基础，但尚未校验互指配对、出口安全空间和各类型专属参数 |
| `Module/GameModule/Session/Session.cs` | `Restart()` 重建 `PhysicsWorld`；`Copy()` 深复制球与地形状态 | 现有重置/预测方向可保留，只需使新增状态继续参与复制和重建 |

原 v0.3 第 3 点执行文档写的是接入前状态；仓库当前已实现五类地形，不能按旧文档的「尚无地形」作为事实。已有未提交改动不在本方案范围内。

## 3. 设计目标与原则

1. **单一职责**：`PhysicsWorld` 负责统一时间轴、候选事件排序和球体/库边接触；地形规则负责地形特有判定和状态转移；`TerrainManager` 负责实例与视图。
2. **开闭与策略模式**：公共调度只认识 `ITerrainRule` 所返回的候选和结果；五类规则分别实现。新增第六类时添加规则与配置映射，不复制世界主循环中的大段分支。接口只包含当前确需的接触查询和应用，不设计万能效果插件。
3. **组合复用与状态模式**：球的主要地形阶段以明确的互斥状态表示，短时入口锁以「球 × 地形」接触记录表示；传送防回跳为球的独立记录。避免一组可互相矛盾的布尔值。
4. **最少知识与依赖倒置**：规则只接收模拟所需的球、地形配置和世界查询上下文，不访问 `GameManager`、Prefab、UI、资源模块；管理器接收世界快照用于表现。`Module`/`Core` 是本项目职责分类，不假定已形成独立程序集边界。
5. **行为契约优先**：每种地形的触发几何、效果、结束条件、碰撞资格都明确记录，不能用同一个 `Duration` 或 `SpeedMultiplier` 字段偷偷代替不同语义。

里氏替换与接口隔离在这里的具体要求是：规则接口不得强迫某一种地形实现不适用的「持续效果」或「配对出口」方法；调用方只依赖接触候选和应用结果。无需让五个 Prefab 继承五级 MonoBehaviour 层级。

## 4. 目标结构与数据流

```text
Module/LevelModule/
  LevelData, TerrainPlacementData, TerrainConfigValidator   # 已校验的关卡摆放和类型参数
Module/TerrainModule/
  TerrainManager                                        # 加载、持有、同步、释放视图
Core/Terrain/
  TerrainBase                                           # 仅表现组件，建议改名 TerrainView（另次迁移可做）
  TerrainSystem                                         # 模拟域入口，持有规则表和接触记录
  ITerrainRule + JumpPad/Tunnel/Pit/ReverseBelt/TeleporterRule
  BallTerrainState, TerrainContactState                 # 可复制、可重建的纯运行状态
Core/Physics/
  PhysicsWorld, ContactSolver                           # 时间轴、通用接触和响应
```

```text
LevelManager → LevelData/摆放快照 → PhysicsWorld + TerrainSystem
PhysicsWorld.FindNextEvent → TerrainSystem.FindCandidate → 按时间/优先级选择
PhysicsWorld.Advance(到事件时刻) → TerrainSystem.Apply/AdvancePhase
PhysicsWorld.Copy → 复制球状态 + 地形接触记录 → 预测使用同一规则
Session.Sync → TerrainManager.Sync → TerrainView
Session.Restart → 重建世界状态，视图重新同步
```

`ITerrainRule` 可设计为 `TryFindContact(...)` 与 `Apply(...)` 两个纯模拟方法；持续阶段的到期/出口事件由 `TerrainSystem` 统一提交给世界调度。规则实例按类型静态注册一次，运行态绝不存放在共享策略对象里。世界只需要一个地形候选来源和一个响应入口，不直接持有五种地形的 `switch`。

### 状态所有权

- `BallTerrainState`：`Phase = Normal/Airborne/InTunnel/TunnelBlocked/TrappedInPit`，阶段对应的地形 ID、剩余路程或几何出口信息。`TeleportTransit` 不是持续阶段，只记录最近出口及脱离触发区条件。
- `TerrainContactState`：按球与地形 ID 记录 `Outside/Inside`，进入只在边界从外到内时产生；离开边界才解锁。必要的短暂安全间距属于该球与出口的接触记录，不是整个地形的锁。
- 地形实例状态只保存真正全局且会影响所有球的内容；五类当前没有证据需要「整个地形进入冷却」。视图高亮可从球状态聚合推导，避免另存 `Airborne/TunnelActive/Submerged` 三份真相。
- 复制、预测、重置包含全部接触记录与阶段；不使用 Unity `OnTriggerEnter` 或墙钟计时器改变模拟结果。

## 5. 五类规则契约

| 地形 | 接触与计算 | 球状态与结束 | 特别约束 |
|---|---|---|---|
| 跳台 | 沿进入瞬间的速度单位方向起飞。以入口速度 `v0` 算目标飞行路程 `D(v0)`，使用策划可调的飞行参数和上下限；运动积分仍由世界求解 | `Airborne`，走完路程或先停球时落地；落地作为世界时间轴事件 | 飞行中禁用已定义的地面接触类别；落地后立即恢复。零速进入不应凭地形朝向凭空生成速度 |
| 隧道 | 明确入口面、通道轴、长度及口径；比较球直径 `2r` 与内口径，并用既有接触容差定义「等于」区间 | 小于：进入 `InTunnel`，以通道出口几何事件离开；等于：`TunnelBlocked`；大于：按入口面法线弹开 | 通道穿越不能用固定 `Duration` 假装出口；半径在通道内变化时需重新判定是否仍能通过 |
| 地陷 | 进入后球心定位到陷区并停住；保持可参与其他球的碰撞解算 | `TrappedInPit`；白球可在下一杆达到配置的高力度阈值后脱出；任何陷球受其他球有效碰撞冲量后脱出 | 黑 8 也能被撞出，地陷永不标记入洞；脱出阈值和推出方向应在规则里显式定义 |
| 反向带 | 每次从外到内经过时令 `velocity = -velocity` | 瞬时效果，无持续阶段；离开触发范围后可再次进入 | `|velocity|` 保持不变；不能靠延时冷却表达「经过一次」 |
| 传送口 | 入口到已校验的配对出口；世界速度矢量逐分量保留，即 `vOut = vIn` | 瞬时转移；球完全离开出口触发区后才允许再触发 | 出生点在出口的安全区域、沿原速度方向留足球半径与接触容差；出口被障碍/其他球占据时按已选规则处理，禁止挤入重叠位置 |

### 接触资格与同刻冲突

先找所有候选中最早的**物理时刻**，再按同刻优先级选一个并重算剩余候选。地形进入、离开、落地、出隧道都作为候选；状态变化不能提前在整个固定步起点结算。默认建议：实质阻挡接触先于拾取/洞口与目标判定，球与球、库边顺序沿现有规则；但涉及「地形与球洞/三角形同刻」时应以策划确定的表为准，并固定稳定 ID 作为最终并列键。

飞行中的「地面物」需要一张统一资格表，至少列出三角形、道具、球洞、其他地形、地面球及库边。当前策划文本只明确不碰地面物，旧决策文档具体到三角形；因此本方案暂建议跳过所有地面交互，库边保持桌边约束，并将地面球、出口传送资格列为确认项。规则不得只在 `Gate` 一处临时判断 `Airborne`，否则三角形目标、道具和洞仍可能先触发。

## 6. 配置与迁移

- `LevelTerrain` 继续负责每关摆放：ID、类型引用、位置、方向、尺寸、成对引用；`Terrain` 继续提供样式/Prefab 引用。保留旧数据读取路径，在 `TerrainPlacementData` 构造/校验阶段转成每种规则的明确参数。原来的通用 `Duration`、`SpeedMultiplier`、`InheritVelocity`、`InheritRotation` 只作为旧数据兼容字段；新策划契约需有明确类型字段，传送保速保向不得被可选开关关闭。
- 隧道口径应是独立的内径配置，不能从地形图片尺寸较短边推断。入口/出口、通道长度与视觉摆放需同一几何定义。
- 传送配对至少保证出口类型正确、无自指、双向引用或明确单向配对规则、出口与球半径的安全空间。不能仅校验 `ExitId` 存在。
- 实施时先建立各地形的输入/输出行为契约，再迁移地形状态与计时，再从 `PhysicsWorld` 移走五类响应，最后整理 Luban 与表现。每步保留真实模拟与预测使用同一算法；现有资源 GUID、Prefab 引用和已修改文件内容不应因架构整理而被无意覆盖。
- `TerrainBase` 虽名为 Base，实际是 sealed 表现组件；建议单独改名为 `TerrainView`，不是实施架构所必需。`TerrainManager` 保留 `Module/TerrainModule`，具体行为留 `Core/Terrain`，遵循已确认的 Module/Core 归属规范。

## 7. 需确认的策划边界与建议默认值

1. **腾空碰撞资格**：文案「地面物」是否包括球、道具、球洞、其他地形？建议全部跳过地面交互，但仍保留库边桌面约束；这比旧文档仅跳过三角形更广。
2. **地陷出杆阈值**：建议配置为归一化力度阈值，不硬编码「必须等于最大力度」；其他球救援建议使用有效法向冲量阈值。
3. **隧道动态变径**：本项目球半径在运动中变化。建议通道内一旦不满足内径，停在当前通道位置并进入 `TunnelBlocked`，避免穿墙或直接传出。
4. **传送出口被占用**：建议本次传送不发生，球留在入口并给碰撞反馈；不能强行覆盖另一球。应决定传送口是双向互指还是允许单向关系。
5. **同刻冲突**：确认地形与球洞、道具、三角形发生同刻接触时的优先级；实现前整理为一张稳定优先级表。

这些是策划未完整规定的行为边界，不应把建议默认值写成已确认需求。每关最多两**种**地形的限制继续保持，不等于最多两个地形实例。

## 8. GitHub 方案调研与取舍

- [Unity Physics Samples](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/master/PhysicsSamples/README.md)：官方样例把触发、接触、碰撞过滤与冲量修改分成独立示例。可借鉴「接触事实与响应分离」及接触过滤思路；样例使用 DOTS/Unity Physics，不适合替换本项目自有连续事件求解器。
- [Unity PhysicsExamples2D](https://github.com/Unity-Technologies/PhysicsExamples2D)：官方 2D 物理示例包含 Sandbox 与组件式 Workshop，适合核对触发区域和几何表现；本项目预测需要复制自有世界状态，直接换为 MonoBehaviour 触发器会产生双重物理真相。
- [unity-billiards-trajectory](https://github.com/vonWolfehaus/unity-billiards-trajectory)：将可见桌球与独立预测物理场景同步、重置，是「预测与正式世界隔离」的参考。其实现基于 Unity 3D 物理多场景，并非可直接套用的地形架构；本项目已有 `PhysicsWorld.Copy()`，保留同一纯模拟规则更合适。
- [Unity ECSGalaxySample 确定性说明](https://github.com/Unity-Technologies/ECSGalaxySample/blob/main/_Documentation/determinism.md)：强调固定时间步和稳定更新顺序；本项目应把地形阶段变化放到统一时间轴，并为同刻事件设置固定排序。该项目的跨平台位级确定性措施不在本次目标内。

未找到同时满足「2D 变半径桌球、连续事件求解、五类地形、可复制预测世界」的成熟开源实现。因此不引入整套第三方框架，借鉴可验证的职责和时间轴原则，保持现有模拟核心。

### 11.1 复用现有 `TerrainBallState` 文件

```csharp
public enum TerrainPhase
{
    Normal,
    Airborne,
    InTunnel,
    TunnelBlocked,
    TrappedInPit
}

/// <summary>一个球的互斥地形阶段及传送退出保护。</summary>
public sealed class TerrainBallState
{
    public TerrainPhase Phase;
    public int PhaseTerrainId;
    public Vector2 PhaseDirection;
    public float RemainingDistance;       // 仅 Airborne 使用
    public int IgnorePortalUntilExitId;    // 与 Phase 独立

    /// <summary>只结束持续阶段，保留独立的传送出口保护。</summary>
    public void EndPhase()
    {
        Phase = TerrainPhase.Normal;
        PhaseTerrainId = 0;
        PhaseDirection = Vector2.zero;
        RemainingDistance = 0f;
    }

    /// <summary>复制可变状态，供预测世界隔离使用。</summary>
    public TerrainBallState Copy()
    {
        return new TerrainBallState
        {
            Phase = Phase,
            PhaseTerrainId = PhaseTerrainId,
            PhaseDirection = PhaseDirection,
            RemainingDistance = RemainingDistance,
            IgnorePortalUntilExitId = IgnorePortalUntilExitId
        };
    }
}
```

`Phase` 用于互斥状态。若策划后续要求「腾空中也可传送」，不能再用单一 `Phase` 表达两者同时持续，而应增加经过明确验证的独立能力位。本期先按第 7 节建议处理腾空碰撞资格。现有 `SimulatedBall.Terrain` 可继续持有此类；无需在 `TerrainSystem` 再保存第二份球阶段。

### 11.2 每球每地形接触记录

```csharp
/// <summary>记录每个球是否仍在每个地形触发区内。</summary>
public sealed class TerrainContactBook
{
    private readonly bool[] _inside;
    private readonly int _terrainCount;

    public TerrainContactBook(int ballCount, int terrainCount)
    {
        _terrainCount = terrainCount;
        _inside = new bool[ballCount * terrainCount];
    }

    public bool IsInside(int ballIndex, int terrainIndex)
    {
        return _inside[ballIndex * _terrainCount + terrainIndex];
    }

    public void SetInside(int ballIndex, int terrainIndex, bool value)
    {
        _inside[ballIndex * _terrainCount + terrainIndex] = value;
    }

    public void CopyTo(TerrainContactBook target)
    {
        Array.Copy(_inside, target._inside, _inside.Length);
    }
}
```

它是预测副本必须复制的世界状态，大小为 `球数 × 地形实例数`，不用每次 `Step` 创建集合。`TerrainRuntimeState.EntryLocked` 和 `CooldownRemaining` 可由此替代；一颗球不会把整个入口锁给另一颗球。

关卡建世界时要根据每个球的出生位置初始化接触记录。出生点若已在触发区内，应标记 `Inside` 并由关卡校验决定是否允许这种摆放；不能把它当作一次进入事件凭空触发。传送落点若恰好落在出口触发区边界，也应立即更新对应球的接触记录。

## 12. 连续时间轴如何接入

### 12.1 当前缺口

当前 `PhysicsWorld.Step` 先执行 `UpdateTerrainTimers(duration)`，再在 `while` 中查找接触。若某球在步中途接触跳台，剩余状态仍按步首统一减少，下个步才会考虑落地；同刻进入/离开事件也无法准确排序。`ContactSolver.Circle` 只返回向内根，并且 `capture=true` 且球心已在圆内时可直接返回 `0`；因此「离开后解锁」必须有独立向外根查询或等价的连续边界求解，不能把现有 `Circle` 反用。

### 12.2 推荐的世界步进流程

```text
Step(fixedDelta)
  remaining = fixedDelta
  while remaining > epsilon 且 (有运动球 或 有本段应到期的阶段事件)
    segment = Prepare(remaining)                // 沿用现有停球/变径截断
    hit = FindOrdinaryContact(segment)          // 球、库边、洞、图形、道具
    terrainHit = TerrainSystem.FindNext(segment, trajectories)
    phaseHit = TerrainSystem.FindPhaseEnd(segment, trajectories)
    next = ChooseByTimeThenPriority(hit, terrainHit, phaseHit)
    AdvanceAllBalls(next.time)
    TerrainSystem.AdvanceState(next.time, pre/post trajectories)
    remaining -= next.time
    Resolve(next)                               // 每次只提交一个事件
    TerrainSystem.UpdateContactBook(next)       // 进入/离开锁
    重新计算轨迹与剩余候选
```

实现时 `AdvanceState` 必须用**本段实际推进时长**，不能预扣完整固定步。零时间事件需要有明确的状态改变或位置分离，避免事件上限内反复命中。`FindPhaseEnd` 至少涵盖跳台落地、隧道出口、通道内半径跨口径、触发区离开；地陷和隧道卡住只由出杆、外部碰撞或整关重置解除，不靠倒计时。`Moving` 当前只检查速度，需确保「飞行停止后立即落地」在同一事件处理完，而非因所有球停住而跳出循环。

### 12.3 向外穿越的求解接口

```csharp
/// <summary>求轨迹球心首次向外穿越静态触发圆的时间。</summary>
public double CircleExit(BallTrajectory ball, Vector2 center, float radius)
{
    Vector2 p = ball.Position - center;
    Vector2 v = ball.Velocity;
    Vector2 h = ball.Acceleration * .5f;
    const double GAP_EPSILON = 1e-5;

    if (p.magnitude > radius + GAP_EPSILON)
    {
        return double.PositiveInfinity;
    }

    if (Math.Abs(p.magnitude - radius) <= GAP_EPSILON
        && Vector2.Dot(p, v) > GAP_EPSILON)
    {
        return 0;
    }

    _coefficients[0] = p.sqrMagnitude - radius * radius;
    _coefficients[1] = 2 * Vector2.Dot(p, v);
    _coefficients[2] = v.sqrMagnitude + 2 * Vector2.Dot(p, h);
    _coefficients[3] = 2 * Vector2.Dot(v, h);
    _coefficients[4] = h.sqrMagnitude;

    int count = _roots.Find(_coefficients, 4, 0, ball.Duration);
    for (int i = 0; i < count; i++)
    {
        double t = _roots.Root(i);
        Vector2 delta = p + v * (float)t + h * (float)(t * t);
        Vector2 velocity = v + 2 * h * (float)t;
        if (Vector2.Dot(delta, velocity) > GAP_EPSILON)
        {
            return t;
        }
    }

    return double.PositiveInfinity;
}
```

上面使用 `ContactSolver` 已有的 `_coefficients` 与 `_roots`，展示向外根过滤条件；正式实现应提取与 `Circle` 共用的四次方程构造，避免重复。`GAP_EPSILON` 应与项目接触容差体系对齐，不应另长期保留一套魔法阈值。规则不自行按帧采样，否则高速球可能一帧跨越地形入口和出口。

### 12.4 同刻优先级示意

```csharp
private static bool IsEarlier(ContactCandidate candidate, ContactCandidate current)
{
    const double TIME_EPSILON = 1e-8;
    if (candidate.Time < current.Time - TIME_EPSILON)
    {
        return true;
    }

    if (Math.Abs(candidate.Time - current.Time) > TIME_EPSILON)
    {
        return false;
    }

    if (candidate.Priority != current.Priority)
    {
        return candidate.Priority < current.Priority;
    }

    return candidate.StableId < current.StableId;
}
```

`Priority` 必须由同刻规则表定义。当前 `EventKind` 顺序是 `Goal → Prop → Pocket → Terrain → Ball → Rail → Gate`；如果要求跳台阻断同刻地面洞/道具，就不能仅在 `FindContact` 里跳过 `Gate`，需要调整资格判定及同刻排序。此项列在第 7 节，待策划确认后写成常量表。

## 13. 五个规则的关键代码与流转

以下只显示改变行为的代码核心；尺寸、零速、边界及对象可用性在关卡入口和候选查询阶段保证，避免在每个策略里重复堆 `if`。

### 13.1 跳台：入口速度决定飞行距离

```csharp
public void ApplyJump(SimulatedBall ball, TerrainPlacementData data)
{
    float speed = ball.State.Velocity.magnitude;
    float flightDistance = Mathf.Clamp(
        speed * data.JumpFlightTime,
        data.JumpMinDistance,
        data.JumpMaxDistance);

    ball.Terrain.Phase = TerrainPhase.Airborne;
    ball.Terrain.PhaseTerrainId = data.Id;
    ball.Terrain.PhaseDirection = ball.State.Velocity / speed;
    ball.Terrain.RemainingDistance = flightDistance;
    // 不改 Velocity 的大小；起飞表现交给 TerrainBase/球视图。
}
```

入口候选要求 `speed > StopSpeed`。对本段直线减速轨迹，`s(t)=v·t−a·t²/2`，解 `s(t)=RemainingDistance` 得落地时间；若判别式小于零或先达到停球时间，则在停球时落地。每次 `Advance` 根据真实位移扣除 `RemainingDistance`，最后钳至零。这样飞行距离有明确的入口球速关系，且被球体碰撞改向后仍能用实际走过的路径长度结算。若策划要求飞行中绝对不碰地面球，跳台阶段的球碰撞候选也应由统一资格表排除。

### 13.2 隧道：几何入口、内径和出口

```csharp
private static TunnelFit CompareDiameter(float diameter, float opening, float tolerance)
{
    float delta = diameter - opening;
    if (delta < -tolerance)
    {
        return TunnelFit.Pass;
    }

    if (delta > tolerance)
    {
        return TunnelFit.Bounce;
    }

    return TunnelFit.Block;
}

public void ApplyTunnel(TerrainContext context, TerrainHit hit)
{
    SimulatedBall ball = context.Balls[hit.BallIndex];
    TerrainPlacementData data = context.Terrains[hit.TerrainIndex];
    TunnelFit fit = CompareDiameter(
        2f * ball.State.Radius,
        data.TunnelInnerDiameter,
        context.ContactTolerance * 2f);

    switch (fit)
    {
        case TunnelFit.Pass:
            ball.Terrain.Phase = TerrainPhase.InTunnel;
            ball.Terrain.PhaseTerrainId = data.Id;
            ball.Terrain.PhaseDirection = hit.TravelDirection;
            break;
        case TunnelFit.Block:
            ball.State.Velocity = Vector2.zero;
            ball.Terrain.Phase = TerrainPhase.TunnelBlocked;
            ball.Terrain.PhaseTerrainId = data.Id;
            break;
        case TunnelFit.Bounce:
            context.ReflectAtEntrance(ball, hit.EntryNormal);
            break;
    }
}
```

`TunnelInnerDiameter` 必须是通行口内径，不取 `min(Size.x, Size.y)`。入口候选只接受由任一端面朝通道内部的速度，且球心横向偏移不超过 `内径/2−球半径`。通过时保持通道内实际速度和变径规则，出口由端面平面接触事件触发；不按 `Duration` 直接传出。若通道内变径达到口径，产生 `TunnelBlocked` 阶段事件。当前实现对 `TunnelBlocked` 只要后续速度大于停球阈值就自动解除，策划没有授权这种救援路径，建议去掉；若将来需要撞出，再单独定义该行为。

### 13.3 地陷：两条明确的脱出路径

```csharp
// PhysicsWorld.Shoot 中先判定整杆是否能成立，再提交地陷脱出。
if (white.Terrain.Phase == TerrainPhase.TrappedInPit
    && power < level.PitEscapePowerThreshold)
{
    return false;
}

if (!CanPlace(white.State.Position, white.State.Radius, WhiteIndex))
{
    return false;
}

// 通过所有拒绝条件后，才修改阶段和出杆状态。
if (white.Terrain.Phase == TerrainPhase.TrappedInPit)
{
    terrainSystem.ReleaseFromPit(WhiteIndex, direction);
}

// 随后沿用原 Shoot 的力度、半径和速度计算。
```

地陷球仍留在 `Balls` 中参与球球接触，不把 `Active` 设成 false，也不写 `PocketStates`。在 `EventKind.Ball` 正常计算碰撞冲量后，把本次冲量传给 `TerrainSystem.OnBallImpulse(ballIndex, impulse, normal)`；达到配置的有效冲量阈值且可找到安全脱出位置时，解除陷住并沿冲量方向赋予剩余速度。黑 8 与白球走同一碰撞救援路径。陷球不应因任意浮点小速度在下一步自动解除。

未达到阈值时，地陷吸收陷球本次获得的速度，使其保持在陷区；另一球按接触解算后的速度继续运动。达到阈值但没有合法脱出位置时，也保持陷住并给接触反馈，不把球移动进障碍。这个规则需在球球冲量提交处显式处理，不能等下一步用 `Velocity > StopSpeed` 猜测是否已被救出。

### 13.4 反向带：进入时一次翻转，离开后重入可再次触发

```csharp
public void ApplyReverse(SimulatedBall ball, TerrainContactBook contacts,
    int ballIndex, int terrainIndex)
{
    ball.State.Velocity = -ball.State.Velocity;
    contacts.SetInside(ballIndex, terrainIndex, true);
}

// 向外穿越事件：contacts.SetInside(ballIndex, terrainIndex, false);
// 下次向内穿越才可再次 ApplyReverse。
```

不设置 `ReverseActive` 或 `Remaining`。反向后球往入口方向退出是预期行为；即使下一轮查询在边界得到 `t=0`，`Inside=true` 也会抑制重复翻转。离开事件必须按连续轨迹求解，不能按若干毫秒冷却代替。

### 13.5 传送口：速度矢量不旋转，出口位置先确认

```csharp
public bool TryTeleport(TerrainContext context, TerrainHit hit)
{
    SimulatedBall ball = context.Balls[hit.BallIndex];
    TerrainPlacementData entry = context.Terrains[hit.TerrainIndex];
    TerrainPlacementData exit = context.GetTerrainById(entry.ExitId);
    Vector2 velocity = ball.State.Velocity;
    Vector2 travel = velocity.normalized;
    Vector2 destination = exit.Position
        + travel * (exit.TriggerRadius + ball.State.Radius + context.ContactTolerance);

    if (!context.CanPlaceAt(destination, ball.State.Radius, hit.BallIndex))
    {
        return false; // 入口响应按已确认的「占用时取消」规则处理。
    }

    ball.State.Position = destination;
    ball.State.Velocity = velocity; // 世界方向与速率均保持。
    ball.Terrain.IgnorePortalUntilExitId = exit.Id;
    return true;
}
```

零速度是否可触发传送应在候选层定案；若允许，必须另给出口摆放方向，不能对零向量归一化。`CanPlaceAt` 至少检查台面边界和其他活动球，也应检查出口处的阻挡地形与几何门。出口若恰在库边附近，单纯沿 `travel` 偏移可能越界；此时不在事件响应里随机寻找点，而应按固定顺序计算候选安全点或拒绝传送。当前方案建议「拒绝并反馈」；配对验证可事先排除恒定不安全的摆放。配对传送口的两个方向均使用同一规则，预测副本得到同样结果。

## 14. Luban 数据设计与迁移顺序

现有生成类型表明：`LevelTerrain` 有 `Position/Size/Direction/TriggerRadius/Duration/ExitId`，`Terrain` 有 `TerrainKind/PrefabLocation/DefaultDuration/DefaultSpeedMultiplier/InheritVelocity/InheritRotation`。这些是当前数据事实；以下是建议新增的**源表字段**，需要策划边界确定后才落表。

| 来源表 | 建议字段 | 适用类型 | 理由 |
|---|---|---|---|
| `Terrain.xlsx` | `jumpFlightTime`, `jumpMinDistance`, `jumpMaxDistance` | 跳台 | 入口球速明确映射飞行路程 |
| `LevelTerrain.xlsx` | `tunnelInnerDiameter`, `tunnelLength` | 隧道 | 通道内径与长度不依赖图片尺寸 |
| `Terrain.xlsx` | `pitEscapePowerThreshold`, `pitEscapeImpulseThreshold` | 地陷 | 分别规定下一杆和他球撞出的条件 |
| `LevelTerrain.xlsx` | 保留 `exitId`；视策划补 `pairId` 或单向标记 | 传送口 | 明确配对关系，避免只校验目标存在 |
| 通用 | 逐步废弃 `duration/speedMultiplier/inheritVelocity/inheritRotation` 的地形通用语义 | 五类 | 避免类型无关字段形成非法组合 |

生成顺序：先备份/确认源表的既有记录与字段；修改 `Configs/GameConfig/Datas/*.xlsx`；运行仓库现有的 Luban 生成脚本，使 `GameProto/GameConfig` 与 `AssetRaw/Configs/bytes` 同步；再调整 `TerrainPlacementData` 的转换与 `LevelData.ValidateTerrains()`。**不要手改生成的 `.cs` 或 `.bytes`**。旧字段若有正式关卡数据，先保留读取并在快照层转换；待所有关卡迁移完成，再另行删除冗余列。`TerrainKind` 枚举值保持不变，避免旧二进制类型错位。

校验应按类型给出可定位的错误：跳台距离上下限及飞行参数，隧道正内径和几何长度，地陷阈值区间，传送目标类型、互指关系、出口安全范围；仍保持每关最多两种地形。涉及最大/最小球径时，以本关球配置的实际范围做几何校验，不只检查静态当前半径。

## 16. 逐项验收情景与风险

| 场景 | 期望 | 主要风险 |
|---|---|---|
| 两球同一固定步进入同一反向带/隧道 | 各自独立触发，不因另一球锁入口 | 接触记录仍意外共享 |
| 球恰在触发圆边界并反向离开 | 本次只触发一次，离开后允许重进 | 零时刻重复事件耗尽迭代预算 |
| 高速球一固定步横穿短地形 | 正确记录进入与离开 | 帧末采样漏掉整段穿越 |
| 跳台中先停球或本步中途落地 | 当时落地，之后恢复地面接触 | 阶段计时提前扣整步 |
| 变径球进入/通过隧道 | 小、等、大及通道中跨口径有明确结果 | 用静态入口半径代替持续判定 |
| 黑 8 陷坑被白球撞击 | 满足冲量和出口空间时救出；未记作入洞 | 球球碰撞后自动错误落袋或脱出 |
| 白球陷坑，低力度/不可放置出杆 | 出杆失败且仍陷住、杆数不变 | 先清状态再发现出杆失败 |
| 传送出口被球占据或靠库边 | 按确认规则拒绝，不生成重叠球 | 强制传送造成穿模或循环 |
| `World.Copy()` 后跑预测 | 预测修改接触锁与阶段不影响正式世界 | 浅复制共享数组 |
| `Session.Restart()`、切关、取消加载 | 状态清零；实例与资源引用回收 | 旧视图残留或异步回调触碰已释放对象 |

风险排序：接触时间轴与同刻排序为高；隧道几何/动态变径、地陷冲量及传送出口为中高；表现改动为低。`TerrainManager.InitializeAsync` 已使用 `LoadGameObjectAsync`，返回实例的销毁交由框架资源管理；实施时若 `await` 后取消或后续 Prefab 检查失败，应让已加入 `_objects` 的实例在既有 `Release()` 路径中回收，不为普通流程加无意义的 `try-catch`。只有需要处理取消并确保释放时才设置明确的清理边界。
