# 道具类型枚举与配置枚举解耦方案

## 背景

道具效果策略的获取依赖 Luban 生成的配置枚举 `GameConfig.PropKind`。该枚举属于自动生成产物，成员会随配置表增删、重命名而变化，不应作为游戏逻辑层的分支契约。

此外，`FlipProp.Effect` 在表现组件里硬编码 `PropEffects.Get(GameConfig.PropKind.Flip)`，存在职责错位：效果类型本应由配置数据决定，而非组件自我声明。

## 目标

1. 逻辑层拥有独立的道具效果类型枚举，与 Luban 配置枚举解耦。
2. 配置枚举到逻辑枚举的转换收敛到唯一入口。
3. 移除表现组件对效果类型的硬编码，效果策略由配置数据注入。

## 方案（方案 A：逻辑枚举 + 单一转换点 + 数据注入）

### 1. 新增逻辑层枚举

文件：`GameLogic/Core/Prop/PropEffectKind.cs`

```csharp
namespace GameLogic
{
    public enum PropEffectKind
    {
        Flip = 0,
    }
}
```

### 2. 新增唯一转换器

文件：`GameLogic/Core/Prop/PropKindConverter.cs`

```csharp
public static class PropKindConverter
{
    public static PropEffectKind ToEffectKind(GameConfig.PropKind kind)
    {
        switch (kind)
        {
            case GameConfig.PropKind.Flip:
                return PropEffectKind.Flip;
            default:
                throw new ArgumentOutOfRangeException(nameof(kind));
        }
    }
}
```

### 3. 策略工厂改为逻辑枚举

`PropEffects.Get` / `PropEffects.Apply` 参数类型由 `PropKind` 改为 `PropEffectKind`。

### 4. 摆放数据持有逻辑枚举

`PropPlacementData.Kind` 类型改为 `PropEffectKind`，在构造函数中通过 `PropKindConverter.ToEffectKind(config.PropKind)` 转换一次。

### 5. 移除组件硬编码

- 删除 `PropBase.Effect` 抽象属性。
- 删除 `FlipProp.Effect` override，组件不再声明类型。
- `PropManager` 直接使用 `PropEffects.Get(data.Kind)` 生成效果策略。

## 数据流

```
配置表 Prop.PropKind (GameConfig.PropKind)
    │  唯一转换点
    ▼
PropPlacementData.Kind (PropEffectKind)
    │
    ├─► PropManager → _effects（表现层策略）
    └─► PhysicsWorld → _propEffects（模拟/预测策略）
```

逻辑层其余代码只认识 `PropEffectKind`，`GameConfig.PropKind` 仅在 `PropKindConverter` 中出现。

## 扩展新道具的步骤

1. `PropEffectKind` 新增成员。
2. `PropKindConverter` 新增 case。
3. 新增策略类并注册到 `PropEffects`。
4. prefab 表现组件无需改动。
