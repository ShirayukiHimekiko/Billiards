## 格式规则

1. 四空格缩进，大括号独立行；条件体、循环体、方法体展开为清晰的多行结构。
2. 每条语句独立一行，字段分别声明，枚举成员逐项换行；不以正则批量拆分分号。
3. using 与 namespace 之间、成员之间、不同职责的逻辑段之间保留适量空行。
4. 运算符及参数逗号后保留空格；长参数列表、复杂表达式、数组与对象初始化器按语义换行。
5. 自动属性访问器、复杂 getter 展开；简单表达式成员保持清晰，不为格式整理改写业务表达式。
6. 保留现有类型名、成员名、序列化字段、命名空间、文件路径及 GUID；本轮不扩大为命名重构或类型拆分。

## 注释规则

1. 类、构造函数、方法、属性及有业务含义的数据字段使用多行 /// XML 文档注释。
2. summary 用中文准确描述职责；参数存在单位、范围、坐标系、默认行为或特殊语义时补 param；返回结果有判定、失败或特殊值语义时补 returns。
3. 枚举项、事件和配置快照字段补充必要的业务说明。私有实现成员按用途补充，避免重复代码字面意思。
4. 局部逻辑使用 //，写在对应代码上方；重点解释连续碰撞、容差、事件优先级、取消及资源清理等必要原因，不逐行复述赋值。
5. 注释以实际实现为准，不根据旧版本玩法文档写入已经失效的说明。
