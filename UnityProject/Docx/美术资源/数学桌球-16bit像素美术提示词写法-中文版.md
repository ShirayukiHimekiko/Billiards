# 数学桌球 · 16-bit 像素美术资源提示词写法（中文版）

> 2026-10-07。基于 `Assets/AssetArt/UIRaw/Raw` 实测数据与 `Docx/美术资源/数学桌球-像素资源-v0.1` 既有产出整理。本文只解决"怎么跟 GPT 说"，不涉及代码实现。

---

## 一、先纠正三个前提

### 1. "16-bit" 和 "像素画" 是两件事

16-bit 指的是**色彩深度**（每个像素存 16 位通道值，约合 RGB 各 5/6/6 位，可呈现数万种颜色）。像素画指的是**绘制方式**（在低分辨率网格上按整数像素作画，再整数倍放大）。

项目现有资源里，`board_background.png` 有 19019 种颜色、`settings_icon_music.png` 有 39203 种颜色——这远超任何 16-bit 设备的显示能力。它们**不是** 16-bit 资源，是"像素风格的手绘插画"。

如果你要的是真 16-bit，判据是这两条，缺一不可：

- 单张图的**唯一色数**控制在 32 色以内（16-bit 调色板实际可用量级）
- 图必须能在**低分辨率源尺寸**（16×16 / 32×32 / 64×64）上完整表达，不能靠放大凑

### 2. 项目现有资源有两条路线，混用了

`assets.csv` 里 `method` 列写明了来源，实测结果如下：

| method | 张数 | 实测特征 |判定 |
|---|---|---|---|
| `builtin_imagegen` | 6 | 色数 1533～39203，边缘半透明占比 0～3% | 像素风格插画，非真像素画 |
| `pixel_geometry` | 14 | 色数 2～6，半透明边缘 0.0% | 真像素画 |

`pixel_geometry` 那14 张是 `build-geometric-assets.py` 用 PIL 在 64×64 / 32×32 / 16×16 画布上直接绘制、再用 `Image.Resampling.NEAREST` 整数倍放大得到的，所以边缘绝对锐利。

`builtin_imagegen` 那 6 张是模型直接出图后 Nearest 放大的，放大只是把连续渐变拉成了块状，**球体高光仍然是渐变而不是色阶**。在游戏里缩小显示时，这些渐变块会互相干涉，产生脏边。

### 3. 直接让 GPT "画 16-bit 像素画" 大概率失败

模型不理解调色板约束，也不保证像素对齐。它会把"像素风"理解成"加了像素滤镜的手绘图"。

要真 16-bit，**GPT不该负责画，而该负责写规格**。

## 二、路线选择：先决定谁来画

| 素材类型 | 推荐路线 | 理由 |
|---|---|---|
| 规则几何（按钮、边框、箭头、虚线圆、进度条） | **脚本绘制** | 已有 `build-geometric-assets.py` 可复用，改颜色和尺寸即可 |
| 有机形状（球体、水晶、道具） | **AI 生成大图 + 降采样量化** | 让模型出造型，下采样后得到真像素 |
| 大面积背景（桌面、面板底） | **AI 生成 + 强制量化** | 需要质感，但必须色数压缩 |
| 文字、UI 排版 | **不做成图** | 项目所有按钮/面板 PNG 都不带文字，交给 Unity Text |

**只有走"降采样 + 量化"才能得到真 16-bit。** 关键在于：AI 出的是高分辨率大图，你主动把它缩小到 32×32，再限制调色板——像素感来自这个降采样过程，不是来自提示词里的 "pixel art"。

## 三、可直接抄的话术（中文）

### 3.1 通用骨架

每张图的提示词按这个五段结构写，缺一段就会跑偏：

```
【用途】<游戏内什么位置、需要多大、是否要透明>
【主体】<画什么，只描述这一个物体>
【风格】<粘贴风格公式，见 3.2>
【硬约束】<禁止项 + 像素规格>
【输出】<只交付这一个文件>
```

### 3.2 风格公式（中文，可直接复制）

项目原有 `design/style-formula.txt` 是英文的，且缺少色阶与调色板约束——这正是它产出非真像素画的原因之一。下面是补齐后的中文版。

**16-bit 修订版**

```
像素画风格，笔触粗壮，边缘为硬边像素块，斜线必须呈现明显的阶梯状锯齿。严禁平滑渐变、
严禁抗锯齿、严禁柔和模糊、严禁 3D 渲染。每个材质的明暗只用两个平色阶，另加一个硬边高光
块和一个硬边暗部块——色阶必须是离散的色带，绝不能是连续渐变。使用固定的有限调色板：
深海军蓝 #17263b（台面）、暖胡桃木棕、象牙白 #fff2d1、青色 #73dedb、珊瑚红 #f9847d、
金色 #ebc774、紫色。造型为简洁醒目的几何轮廓，统一使用深海军蓝描边。光源柔和，来自左
上方。氛围平静有趣的街机感。高对比度、画面不拥挤，在 32×32 源分辨率下依然清晰可辨。
```

这段相比原版补齐了四件事：明确禁止渐变与抗锯齿、规定"每材质两个平色阶加一高一暗"、给出具体色值、声明 32×32 源分辨率。

### 3.3 硬约束段（这段是能不能出真像素的关键）

```
硬性约束：必须是按32×32 源分辨率作画的真 16-bit 像素画；唯一颜色数不超过 32 种；只允许
硬边像素，不得出现平滑渐变；不得出现抗锯齿边缘；不得 3D 渲染；不得水印；不得文字；不得
签名。只交付所请求的这一个资源，不要样机图，不要场景，不要道具，不要展示板。物体居中，
完整可见，背景为真实透明通道（不要棋盘格）。
```

必须包含的四项：

- `按 32×32 源分辨率作画` —— 让模型内部按低分辨率思考
- `唯一颜色数不超过 32 种` —— 色数上限
- `不得出现平滑渐变、抗锯齿边缘` —— 反复强调
- `只交付所请求的这一个资源` —— 防止模型给你拼图

### 3.4 完整示例（球体，透明背景）

```
【用途】风格化概念稿。资产类型：单个独立游戏精灵图，一颗从正上方俯视的白色桌球。

【主体】一个正圆的圆盘，位于正方形画布正中，四周留有充足透明边距。按32×32 像素网格
设计后再放大。球体主体为象牙白 #fff2d1，只用两个平色阶：中间调覆盖右下三分之二区域，

细青色 #73dedb 装饰环。轮廓必须读作由阶梯状像素拼成的正圆，边缘呈明显块状。

【风格】像素画风格，笔触粗壮，边缘为硬边像素块，斜线必须呈现明显的阶梯状锯齿。严禁

硬边高光块和一个硬边暗部块——色阶必须是离散的色带，绝不能是连续渐变。使用固定的有限调
色板：深海军蓝 #17263b（台面）、暖胡桃木棕、象牙白 #fff2d1、青色 #73dedb、珊瑚红
#f9847d、金色 #ebc774、紫色。造型为简洁醒目的几何轮廓，统一使用深海军蓝描边。光源柔和，
来自左上方。氛围平静有趣的街机感。高对比度、画面不拥挤，在 32×32 源分辨率下依然清晰
可辨。

【硬约束】必须是按 32×32 源分辨率作画的真 16-bit 像素画；唯一颜色数不超过 32 种；只允许
硬边像素，不得出现平滑渐变；不得出现抗锯齿边缘；不得 3D 渲染；不得水印。球面上不得有数字、
不得有加号或减号符号、不得有箭头、不得有投射在地面的阴影、圆形外不得有光晕、不得有背景
```

### 3.5 各类素材的差异段

在通用骨架基础上替换"主体"段即可。

**几何类（按钮、面板、边框）— 建议改用脚本**

`button_normal`、`ui_panel`、`power_frame` 这类规整形状，AI 生成的边缘必然不整齐。项目现有做法（`build-geometric-assets.py`）更可靠。若一定要用 AI，主体段写：

```
一个横向长方形UI 面板，四条边的描边宽度完全一致，全部由 1 像素宽的阶梯状边缘构成。四个
角的阶梯形状互为镜像对称。描边粗细在每一边都必须相同。内部平整区域是单一不间断的深蓝
填充，不要纹理、不要光照、不要暗角、不要渐变。
```

关键句：`四条边宽度完全一致`、`单一不间断填充`。

**虚线圆与瞄准箭头**

```
一个由离散 1 像素短划段组成的虚线圆，每段短划长度完全相同，沿圆周等间距分布，短划之间留
有干净的空隙。圆的内部完全是空透明。不要填充、不要渐变、不要光晕。
```

AI 常把虚线画成连续或间距不均，必须写明 `每段短划长度完全相同`。

**背景类（桌面）**

```
一张完全空白的桌球台面：中间是一大块平整的深海军蓝台呢，外圈包一圈阶梯状胡桃木木质边框。
台呢内部是单一平色，只允许有极低对比度的像素抖动纹理——不要任何物体、不要球、不要袋口、
不要三角形、不要道具、不要 UI、不要文字、不要光照渐变。铺满整个画布。
```

必须写 `完全空白`，否则模型会自己加球。

## 四、拿到图之后必须做的后处理

这一步不做，前面所有提示词都白费。

### 4.1 降采样到源分辨率

```python
from PIL import Image
im = Image.open('raw/ball_normal.png').convert('RGBA')
small = im.resize((32, 32), Image.Resampling.LANCZOS)   # 面积缩小时用 LANCZOS
final = small.resize((128, 128), Image.Resampling.NEAREST)  # 放大必须用 NEAREST
final.save('sprites/ball_normal.png')
```

关键点：缩小时用 LANCZOS（抗锯齿有助于后续量化），**放大必须用 NEAREST**。项目现有脚本 `build-geometric-assets.py` 的 `save()` 函数就是这个做法。

### 4.2 量化到固定调色板

```python
PALETTE = ['#17263b', '#fff2d1', '#73dedb', '#f9847d', '#ebc774',
           '#8b5a3c', '#2f4a63', '#a08b6a']   # 8 色，覆盖全部用途
pal = Image.new('P', small.size)
flat = small.convert('RGB').quantize(palette=pal, dither=Image.Dither.NONE)
out = flat.convert('RGBA')
```

`dither=NONE` 很重要。用 Floyd-Steinberg 抖动会在小尺寸上产生噪点，破坏可读性。

### 4.3 验收（写成脚本，每次必跑）

项目现有 `design/文件检查结果.json` 就是这个用途。按实测标准检查：

| 检查项 | 通过标准 | 参考实测值 |
|---|---|---|
| 唯一色数 | ≤ 32 | 现几何资源 2～6 色 |
| 半透明边缘占比 | 0.0% | 现几何资源全部 0.0% |
| 等效源分辨率 | 必须是 16/32/64 的整数倍 | `shot_available` 实测 16×16 |
| 水平垂直边 | 不得出现灰阶羽化 | — |
| 尺寸 | 与 `assets.csv` 声明一致 | — |

半透明边缘占比的检测方法（本次用的就是这个）：

```python
px = im.load(); w, h = im.size
mid = total = 0
for y in range(0, h, max(1, h // 80)):
    for x in range(0, w, max(1, w // 80)):
        if px[x, y][3] > 0:
            total += 1
            if 5 < px[x, y][3] < 250:
                mid += 1
print(f'{mid / total * 100:.1f}%')
```

真像素画的这项指标必须是 0.0%。`toggle_active.png` 当前是 2.3%，说明它带抗锯齿，不是真像素画。

## 五、你应该直接跟 GPT 说的话（最简版）

如果不想看上面的长模板，按这个顺序发这三句：

**第一句——先要规格，不要图**

> 我要给一个俯视像素风桌球游戏做一批 16-bit 像素美术资源。请先帮我确定规格：一张 32×32 源分辨率、最多 32 色的球体，明暗色阶应该怎么分配？高光和暗部各占多少比例？用哪些具体色值？

**第二句——让 GPT 写提示词，你审**

> 按我们确定的色板和像素规格，帮我写三张图的完整生成提示词：白球、翻转道具、空白信息面板。每张都要包含【用途】【主体】【风格】【硬约束】四段。硬约束里必须写明：按 32×32 源分辨率作画、唯一颜色数不超过 32 种、不得平滑渐变、不得抗锯齿、只交付单个资源。

**第三句——最后才让它出图**

> 用上面确认的提示词，生成这张图。

这样倒过来做，比一句话要求"画 16-bit 像素画"的成功率高得多——模型的文本理解能力远强于它对像素网格的控制力。

## 六、你可能忽略的变量

- **"16-bit" 这个词本身有歧义**。如果你告诉模型"16-bit"，多数会理解成"80 年代游戏机的色彩质感"，也就是手绘感加有限色，跟真像素网格是两回事。措辞上用 `按 32×32 源分辨率作画` 比用 `16-bit` 有效得多。
- **模型版本差异**。`gpt-image-1` 已公告 2026-10-23 停用，且尺寸只支持 1024×1024 / 1024×1536 / 1536×1024；`gpt-image-2` 起支持任意尺寸（宽高须为 16 的倍数，宽高比 1:3～3:1，最大 3840×2160）。出图请用 `gpt-image-2`，旧版可能在迁移后直接失效。
- **尺寸参数帮不上像素对齐**。传 `size` 只能拿到大图，像素感仍要靠 4.1 的降采样。指望 API 参数直接产出 32×32 是行不通的。
- **一致性成本**。每张图单独生成会有色差和笔触差。要么每张都严格粘贴同一份风格公式（项目现有做法），要么在拿到第一张满意的图后用 `images.edit` 以它为参考迭代。
- **Unity 导入设置**。项目里 `ball_normal.png` 的 importer 已经是 `filterMode: 0`（Point）、`mipMap: 0`、`alphaIsTransparency: 1`。新资源必须保持这套设置，否则像素边缘会被插值模糊。
- **别忘了分辨率适配**。像素图在1080p 下按整数倍放大才锐利。如果项目是自适应分辨率（`UIModule.cs` 里按 `referenceResolution / Screen.width` 算缩放），非整数倍缩放会重新引入模糊。桌球游戏建议锁 1920×1080 设计分辨率。
