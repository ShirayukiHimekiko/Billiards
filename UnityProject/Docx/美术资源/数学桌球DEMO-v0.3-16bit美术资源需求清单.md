# 数学桌球 DEMO v0.3：16-bit 像素美术资源需求清单

## 1. 依据与范围

依据用户提供的《数学桌球 DEMO 策划案 v0.3》（2026-10-09），整理游戏内可见的世界物件、状态反馈、地形、道具和 HUD 美术需求。本清单是制作规格与需求分析，不代表资源已制作、导入或接入。

策划案尚未确定完整关卡结构、传送口配对数量、半径边界行为及显影/预演的最终获取方式。因此先制作可复用的通用资源，不按关卡数量或洞数量复制图像。开始界面、选关、设置界面的美术不属于本次 v0.3 玩法清单。

**用户对本清单的补充确认**：白球主体只制作一张图；20～24 档指蓄力条的显示档位，不是白球精灵数量。策划案第 10 节把“20～24 档精灵”写在“半径变化”一行，与此确认不一致，本清单按用户确认后的需求执行。项目其他 v0.3 执行文档中的白球 24 档资源预算不适用于本清单。正常、逆转、冻结、疾变仍可使用独立状态标识。

**球桌出图方式补充确认**：球桌交付一张完整俯视图，台呢、库边、桌框和洞口承托在同一张图中；不继续把库边与边角作为最终独立出图清单。洞的四态仍需在完整球桌图上用独立状态层表达。

## 2. 风格和尺寸总规范

- “16-bit 风格”按复古主机时代的像素画视觉理解，不等同于要求 PNG 使用 16-bit 色深。使用有限而统一的色板、离散明暗、高对比轮廓、清晰像素阶梯；不使用模糊、连续渐变与抗锯齿边缘。旧文档中的“单图不超过 32 色”可作为本项目生产约束，不是 16-bit 风格的定义。
- **100×100 px 作为独立物件和 UI 图标的默认交付画布**：透明背景、视觉中心与锚点统一，建议主体留出边距。图标可先按 50×50 逻辑像素绘制，再以最近邻放大 2 倍到 100×100；极简符号也可用 25×25 放大 4 倍。不要把高分辨率平滑画面缩放后直接当成像素画。
- 完整球桌背景、力量条、轨迹线、圆环与任意形状的三角形 **不能强制制作成单张 100×100**。完整球桌按最终画面比例制作一张横向图片；力量条可使用可复用段，轨迹线、圆环与任意三角形按像素网格绘制。
- 图像文件尺寸不等于 Unity 世界尺寸或碰撞半径。白球主体只需一张 100×100 透明图，半径变化使用同一张图显示；圆心、锚点及最小显示尺寸的可读性仍需在实际画面规格确定后处理。蓄力条的档位数量也不决定球的碰撞半径精度。
- 世界图标与 HUD 应共用符号语义；例如“逆转”始终是内收箭头，“冻结”始终有冰壳形状。颜色是辅助，不能成为洞态或地形的唯一识别方式。
- 面向 Unity 的像素资源建议透明 PNG、Point 采样、关闭 mipmap；在最终显示尺寸用整数倍缩放。字体选择或制作可读的像素字形，动态数字和文字由字体渲染，不逐字做图片。

## 3. 世界基础物件

| 资源 | 建议制作内容与尺寸 | 作用 | 优先级 |
|---|---|---|---|
| 完整球桌背景 | **1 张横向完整俯视图**，同图包含深蓝台呢、库边、桌框和洞口承托；尺寸随最终画面比例定，不套 100×100 | 提供球与几何提示的安静底色，同时明确桌边、碰撞区域与洞位；洞态标识另作独立覆盖层 | 必需 |
| 白球主体 | **1 张 100×100 透明图**，球心与锚点居中 | 作为可变半径白球的唯一主体图；画面中的大小随实际半径变化，球的物理半径仍由逻辑决定 | 必需 |
| 白球状态覆盖层 | 外扩箭头、内收箭头、冰壳、疾变符号各 1 套；独立图标可用 100×100 画布 | 分别标识常态、逆态、冻结、疾变，避免仅靠球体换色辨认 | 必需 |
| 白球阴影/离地标记 | 1 套可复用像素阴影，跳台时可改变偏移或显隐 | 说明球是否腾空，以及其与地面三角形、洞的交互区别 | 必需 |
| 黑 8 球 | 固定半径的球面与清晰“8”标记，默认 100×100；需要滚动时再追加 2 帧或方向变化 | 明确通关目标，并与可变半径白球区分 | 必需 |
| 三角形目标 | 顶点、边段、填充/描边、奖励占位标识各 1 套；按关卡顶点组合，不用固定三角形整图 | 表示几何判定对象及奖励来源；任意三角形的边长和角度不能依赖一张 100×100 正三角形 | 必需 |
| 三角形内切/外接提示 | 两类像素线型或圆弧样式，不固定圆半径 | 显影道具与预亮帮助共用，明确内切圆和外接圆的不同角色 | 必需 |
| 洞四态 | 无法使用、上锁、已开启、已进球各 1 套，共享于所有洞；标识可用 100×100 | 无法使用态保留平坦或封闭标识而不画黑色洞口；上锁显示锁纹；开启显示深色洞口；已进球显示填充/入球记号。在最小显示尺寸仍须可区分 | 必需 |
| 钥匙与绑定标记 | 钥匙基础图标 1 套，钥匙编号/轮廓标记按配对规则复用 | 标明奖励与对应洞的关系；多组配对不能只靠颜色区分 | 必需 |

### 白球与蓄力条的数量说明

白球主体预算为 **1 张图**，不制作 20～24 档白球，也不制作由此推导出的 48 帧序列。**20～24 档属于蓄力条**：玩家拉动蓄力时，亮起的格数表达当前力量档位。美术可提供条框、未点亮段、已点亮段和端帽等少量可复用组件；程序按当前档位重复排布或切换显示，无须为每个档位各画一张整条图片。若之后确定需要不同力度区间的警示色，也应先复用段图并换色，而非扩增白球图像。

## 4. 八种道具

每种道具至少提供 **1 张 100×100 透明拾取图标**；持续效果可共用同一语义图形，另配 HUD 小图标版本或缩放规范。

| 道具 | 必备图形 | 游戏中的信息作用 |
|---|---|---|
| 状态逆转 | 双向/内收箭头，青蓝辅助色 | 表明白球半径演化方向切换；本关持续状态在 HUD 保留 |
| 冻结 | 冰壳或雪晶轮廓 | 表明本杆半径不再演化，需与“球停止运动”视觉区分 |
| 复原 | 回到基准圆的回环箭头 | 表明拾取后半径立即恢复；只需短时拾取反馈，不常驻 HUD |
| 疾变 | 叠层快进箭头或加速刻痕 | 表明本杆半径变化速率加倍；不能误画成球速加快 |
| 显影 | 内切圆与外接圆的双轮廓图案 | 表明本关三角形几何圆显形；不直接显示答案数值 |
| 预演 | 轨迹点线与小半径曲线 | 表明下一杆瞄准阶段可查看轨迹与半径演化，而非普通瞄准线 |
| 加杆 | 球杆/杆数符号配动态 +1、+2、+3 文本 | 表明即时补充剩余杆数；三档数值可用文字排版，不必画三套完整图 |
| 钥匙 | 钥匙轮廓，配对色/形状标记 | 表明拾取即解锁指定洞，并支持与洞的对应提示 |

道具拾取可共用一套像素爆闪/上浮反馈；为每个道具重复绘制特效不是首批必要工作。

## 5. 五种地形

| 地形 | 建议资源与尺寸 | 作用与状态要求 |
|---|---|---|
| 跳台 | 斜坡/起跳箭头基础图；可按 100×100 片段拼接，另有腾空阴影和落地点标记 | 玩家进入前能辨认起跳方向，飞行中能看出“离地”，避免误判三角形碰撞失效 |
| 隧道 | 入口、出口、可拉伸中段与口径刻度；不能只做固定 100×100 整体 | 让玩家看懂通行宽度。通过、卡住、弹回可共用主体，再分别给出畅通、挤压、碰撞反馈 |
| 地陷 | 洞沿/凹陷底部；陷入时增加球的遮挡层或边缘压暗 | 区分“球被困”与“黑 8 已进洞”，并提示仍可由下一杆或其他球救出 |
| 反向带 | 反向箭头图案和可平铺带体；100×100 片段 | 在接触前预告速度方向翻转 180°；箭头朝向应随带体摆放而变化 |
| 传送口 | 入口/出口共用的门形基础、配对符号、2 帧左右像素脉冲 | 玩家能识别成对关系和出射方向；配对数量未定，先做可换色且可换形的通用版本 |

五种地形必须首先靠轮廓或图案区分；颜色只用于强调状态。每关最多两种地形是**关卡配置约束**，不是美术资源只需做两种。

## 6. 判定、引导与运动特效

| 表现 | 建议制作方式 | 作用与必要性 |
|---|---|---|
| 撞击失败的同心目标环 | 统一像素线宽/短划样式，按目标半径绘制或用离散圆环档位；不适合固定 100×100 整图 | 0.4 秒内显示目标半径在球内/外及差距，不画两个答案环；核心教学反馈，必需 |
| 连续失败后的预亮圆 | 复用内切/外接圆线型，加短时脉冲帧 | 第 5 次及之后每 2 次失败触发，帮助玩家发现正确圆，必需 |
| 判定通过 | 红色硬边闪光、三角形碎裂小片 2～4 帧 | 说明判定成功、奖励发放与目标消失，必需；具体色值应兼顾警示色语义 |
| 判定失败/弹回 | 少量碰撞火花或边缘闪线 1～2 帧 | 强调真实碰撞和弹开方向，建议首批制作 |
| 瞄准与力量 | 像素箭头、虚线段、接触点标记 | 告诉玩家本杆方向与力量；普通瞄准和预演轨迹应有不同线型，必需 |
| 预演半径曲线 | 线段、节点、起终点符号和小型面板边框 | 显示本杆半径随轨迹的变化，按实时预测生成，不能做成一张固定曲线图，必需 |
| 钥匙与洞连线 | 同色虚线段，配对时附形状/编号标记 | 使一钥一洞的硬绑定可见，必需 |
| 入洞与传送 | 洞口吸入/填充帧、传送入口/出口脉冲 | 说明黑 8 进洞计数与传送位置变化；可在基础功能后细化 |

50 ms 定格是时间控制，不需要单独的图片；环半径、轨迹和曲线由游戏数据决定，美术提供像素线型、端点、边框和配色规范即可。

## 7. HUD 与结果界面

| 资源 | 建议尺寸 | 作用 |
|---|---|---|
| 持续效果图标槽与四类球状态图标 | 图标默认 100×100，槽位按 HUD 缩放 | 左上角显示当前正常/逆转/冻结/疾变及持续效果；一次性道具只短暂提示 |
| 剩余杆数图标、黑 8 进度图标 | 默认 100×100，数字由字体显示 | 右上角让唯一失败条件和通关进度一眼可读 |
| 20～24 档蓄力条 | 条框、未点亮段、已点亮段和端帽；小组件可放在 100×100 画布内交付，整条按界面长度拼接 | 底部用亮起的格数显示蓄力 P；档位是蓄力显示的分段，不是白球图片或物理半径的离散档 |
| 洞态/钥匙小图标 | 复用世界四态与配对符号，可输出 100×100 同源版 | 在 HUD 按需展示锁洞和钥匙关系；避免现场物件被其他元素遮挡时失去信息 |
| 重置按钮 | 100×100 的正常、按下两态 | 对应无限次单键重置；勿使用“悔棋”图形误导为撤销上一步 |
| 预演信息框 | 可拉伸边框、标题标识、曲线图例 | 清楚区分“当前状态”和“下一杆预演”；线与曲线仍由数据实时绘制 |
| 通关/杆数耗尽反馈面板 | 可拉伸边框与胜/负标识，文字动态显示 | 在完成或失败时给出明确反馈和重置/继续入口；无需为每关单独画图 |
| 像素字体/数字规格 | 按实际屏幕最小字号定，不套 100×100 | 保证杆数、+1/+2/+3 和菜单文字可读；优先复用可满足风格的现有字体 |

## 8. 制作批次与待确认事项

1. **核心判定批**：完整球桌背景、单张白球、黑 8、可变三角形、瞄准线、目标环、通过/失败反馈。对应策划案 M1～M2。
2. **规则识别批**：八道具、四洞态、钥匙配对、五地形及必要的腾空/陷入/传送状态。对应 M3～M4。
3. **界面收口批**：持续状态、杆数、黑 8 进度、20～24 档蓄力条、重置与结果面板、预演曲线。对应 M5。

制作前需确认：目标平台和最低显示分辨率、球桌在屏幕中的最终像素尺寸、白球最大/最小直径与 PPU、三角形视觉线宽、传送口配对标记规则，以及显影/预演最终是拾取奖励还是求助按钮。这些会影响实际尺寸或 UI 数量，但不影响前述资源类别。

## 9. 最小交付口径

首批可按“**1 张完整球桌背景 + 1 张白球主体 + 1 个黑 8 主体 + 4 类球状态层 + 4 类洞态 + 8 道具图标 + 5 地形基础套件 + 三角形组件 + 20～24 档蓄力条组件 + HUD 其他基础组件 + 反馈线型与特效**”估算工作量。蓄力条的 20～24 档由可复用段图组合显示，不等于需要 20～24 张蓄力条图片。这里的“套件”可能包含多个片段或帧，故不能把类别数直接当 PNG 张数。先做一张包含最小显示白球、三角形、洞、两种地形和 HUD 的实际游戏画面样张，再锁定像素密度与后续批量制作规格。
